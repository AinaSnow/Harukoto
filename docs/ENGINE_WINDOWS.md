## 快照准备与归属

WindowsDictionary.load 接受基础快照目录（含 base-dictionary.json），可选主题仓库目录及个人 TSV 路径。通过现有 Snapshot.load 校验四份基础数据的清单、大小、SHA256、原生格式和 SQLite 完整性，并保持只读文件保护句柄。基础文件路径固定为绝对路径，查询不会因工作目录变化打开另一份数据库。

准备时复制基础日语及活用词条，按正式顺序追加个人表、主题词条，并按权重稳定排序。主题词条保留 theme 标志。省略可选路径表示不加载对应来源；明确指定的主题路径必须能读到有效快照，坏主题或个人文件拒绝整次准备，不产生半份词库。个人文件最初不存在按现有加载器规则视为无个人表。来源读完后词条固定在内存，之后修改源 TSV 不改变已准备对象。

完整对象的 generation 摘要包含基础代次、主题标识、个人内容指纹和实际合并词条的全部字段。即使主题发布方错误地复用同一个目录名，实际词条内容变化也会生成不同摘要。这个摘要用于内部对象识别，本批没有新增 IPC 版本报告。

读音索引保存每种 reading 对应的原词表位置，发布后不修改。查询先取完整 input 的全部词条；如果满足现有 mixedReading 的全字母、输入长 5～24 条件，再取长度 3～10 子串对应的 source 为空词条。位置排序去重后复制成一次查询的视图，保留同权重顺序和首匹配规则；显式英语／拼音别名不因子串命中进入混打。中文锁定时合并不读取日语表，可直接使用空视图。

这只是缩小传给正式合并函数的等价词条集合，没有改变字典内容、词权重、候选扩展预算、主题名称提升和追加顺序。混打的长度／来源规则仍由 MixedComposition.h 定义；以后改变这些规则时必须同时审查索引筛选条件及全页对照。索引增加快照内存，尚未单独测量成本，不宣称总内存下降。

ServerConnection 构造时可持有 shared_ptr<const WindowsDictionary>，整个连接固定这一代。每个 Work 再持有同一指针，query 必须与任务持有的对象完全一致；调用新词库查询旧任务会报错。服务端使用对象身份隔离连接任务，查询对象检查词库归属，两者职责不同。

旧连接销毁后，只要后台任务还持有旧 Work，旧词库和 SQLite 文件保护仍在。任务完成或丢弃、所有引用释放后才解除保护；连接断开或取消仍会拒绝旧结果发布。这实现了资源寿命保护，不是正在组字时自动升级词库：本批没有切换接口，后续须在明确边界创建新连接并迁移必要状态。

## 查询与提交

一次查询创建独立核心会话，并在执行该查询的线程上打开、使用和关闭独立 WordEvidence。共享对象的准备用 SQLite 连接不参与并发查询；只读原生词库与词条向量共享，SQLite statement 和可变会话均不跨线程复用。仍需后续测量每次重建／打开连接的成本。

查询恢复输入、简繁标志和已选片段上下文，调用正式 Windows 候选合并。随后按页执行至多三轮原有展开，每轮通过 appendCandidateExpansion 追加，已有候选及核心索引保持不变。先转换有效候选并检查当前页末尾之后是否还有一项；确认 more=true 后无需预先计算更晚的页。不足时继续原轮次，最后一页与空页必须用尽原预算才能确认没有下一页。协议最后合法页 4095 不允许继续翻页，只需当前页足够。

返回正文是实际可提交文字：原生候选去掉只用于显示的拼音尾部，消费范围来自核心；SQLite／日语／主题等直接候选消费完整输入。annotation 写入协议 Candidate.reading 字段，包含日语假名或正式合并提供的来源说明。它不是纯假名字段，未来候选 UI 应按注释呈现。

每个新结果中的稳定 ID 为完整合并列表索引加一，并与来源请求号／组字／会话一起验证；分页继续每批 16 项。转换会去掉显示尾部并过滤空正文／零消费，因此停止条件使用转换后的数量，不能直接数原始 choices。转换游标仍按原合并位置编号，过滤不压缩 ID。所有页重建相同前缀、按所需深度扩展后切片，没有跨请求缓存或共享可变核心。字节预算、正文编码或消费范围不合法时拒绝该页，不把坏文字交给 Select。

服务端在部分选词后保留 chineseLocked，后续查询使用正式的中文锁定分支，避免把残余拼音重新当成完整日语触发；输入清空、取消或完整提交解除锁定。片段上下文继续使用上一批的 64 字节上限。Select 仍由服务端已验证候选生成提交回复，重复请求返回原结果，不再次消费拼音；它尚未迁入核心学习或完整上下文状态。

基础活用词条参与普通候选合并；F6 活用面板、完整按键行为、标点和全部混打行为尚未接入。不能用“活用词条已加载”宣称整个活用交互已经迁移。

## 自动验证

engine_windows_full 使用临时目录复制全量基础数据，添加只有 SQLite 中存在的测试词，再用正式 Python 工具制作两代有效快照、导入并启用 FF14 全量主题。用户安装、词库仓库和配置不参与测试。

- SQLite 中的“旧补词／新补词”分别在两代出现，证明测试确实使用各自数据库，而非原生候选碰巧存在。
- 检查 riben 的“日本／にほん”独立候选与读音注释、eat 的“食べる”、FF14“特级恢复药／特級恢復藥”；选择这些候选后核对正文、消费长度及无剩余拼音，并验证重复选择走缓存。
- 按全部页逐项对照正式 windowsCandidates＋三轮 appendCandidateExpansion 的 ID、实际提交文字、消费范围与注释，包含 SQLite、日语、FF14、未完成拼音及中文锁定分支。该对照用于验证适配接线，不作为新的语言准确率。
- 四个真实线程各自持有查询对象并独立打开 SQLite，分别检查“中国／中國”和日语假名，共 24 次完整合并查询；服务端状态仍在各自所属线程使用。
- 修改个人表后新对象采用新词，旧查询仍得到旧词；跨快照查询拒绝，取消后旧结果不能发布。只保留 Work 时旧文件仍不可写，最后引用释放后文件可写；损坏新个人表导致准备失败，旧对象继续可用。
- 索引回归在临时基础 romaji 表加入同读音、同权重的受控词，验证日语片段处于中文前／后／中间时仍得到完整混打。逐页对照完整原词表的正文、ID、消费、注释和顺序，包含排除英语子串、声调／分隔符、主题简繁和中文锁定。最初受控词放入个人表／六字段基础行，因既有来源约束被正确拒绝，改用三字段基础 romaji 行后通过；未放宽生产加载器校验。
- 按页扩展回归在临时原生表增加 45 条同读音词，保留权重顺序与 context 尾段；简繁全部页均与无条件三轮展开的参考路径逐项对照，并检查末页之后和第 4095 页为空且 more=false。另经真实 ServerConnection 连续翻页，选择末页词并验证部分消费／剩余输入及重复选择不再消费。原有主题名称、混打、声调和中文锁定对照继续保留。

为控制测试耗时，多字输入的中间按键用空候选完成，只在最终输入运行完整合并。测试覆盖最终实际查询、选择及资源寿命；没有逐键性能数据，也没有实际应用插入／绘制、进程间通信或更新恢复验收。

## 下一步

现在可在同一实验服务模型中通过有界执行器查询真实中文／SQLite／日语／FF14 候选。逐键分阶段测量及第一项读音索引优化已完成，下一阶段实现认证本地管道、独立进程生命周期与 TSF 迁移，继续跟踪长前缀搜索、队列竞争及额外索引内存。快照准备仍是独立同步操作，尚无后台准备任务或相应管道回复；按键接受、未确认选择恢复、词库空闲边界切换、端到端延迟和多应用实际占用仍需验收。
