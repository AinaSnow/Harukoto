# 真实中文核心适配器

WIN-03b 第四批，2026-11-10。Windows/EngineCore.h 的 CoreDictionary 将真实原生拼音核心接入[服务端任务模型](ENGINE_SERVER.md)。测试可以从 .build/windows/ime/native-pinyin.tsv 加载全量基础词库；不注册输入法、不修改用户词库，不改变 alpha.22 安装包。

## 实现范围

CoreDictionary 只解析一次原生词库，副本通过 shared_ptr 保留同一个 MPNLexicon。核心内部本来使用 shared_ptr<const Lexicon>，加载后词库不变；每次 query 创建、使用并销毁自己的 MPNSession，线程之间不共享可变会话。后台调用者必须持有自己的 CoreDictionary 副本，或保证被引用对象一直存活；ServerConnection 仍只能在所属线程调用。

查询从 Work 取得规范化输入、简繁标志、分页号和已选片段上下文。在新核心会话中恢复上下文，再逐字重建输入；拒绝核心不接受的字节序列或意外产生隐式提交的情况，不悄悄修改输入。协议的字符范围大于真实拼音语法，例如前导单引号、ni9 虽能通过字符检查，但核心拒绝后适配器会抛错。服务宿主仍需把失败转为定义好的错误／断连处理，不能直接忽略。

当前每次重建输入会重复逐字解码，并执行核心现有三轮有界候选扩展；这是正确性原型，尚未优化逐键延迟。没有修改原有搜索预算或宣称无限候选。

## 候选与部分选择

每批返回最多 16 项，属于实验通信批次，不是正式候选窗的分页大小或候选总数上限。服务端记录页号：PageNext／PagePrevious 前后移动，Refresh 保留页号，输入／删除／选择／取消重置页号。页号上限 4095；到达数据末尾返回空列表且 more=false。生产交互还需完善末页停留和按需扩展的体验。

候选 ID 使用本次完整重建结果中的核心索引＋1，仍须与来源请求号／组字／会话一起验证。同一个输入、上下文和简繁模式的各页都先完成同样扩展再切片，避免分页时索引来自不同重建阶段。超过消息正文限制的异常候选拒绝整次查询；不能静默截掉提交文本。

新增只读核心 API mpn_candidate_literal_tail，用于区分显示尾部与实际提交。某些候选显示“已转换文字＋未完成拼音”，mpn_choose 实际只提交前面的转换文字；适配器去掉显示用尾部，同时保留候选的 consumed 范围。测试逐项调用真实 mpn_choose，对照实际提交文本与剩余输入，不只比对两个相同的元数据实现。

服务端 Select 仍根据已验证的候选保存提交结果和剩余拼音，不重放选择按键。部分选择时保留已选文本作为后续查询上下文，当前最多 64 个 UTF-8 字节，超限清空；输入清空、取消或完整提交清空上下文。实际查询由 mpn_set_segment_context 规范化。这个有限上下文不是完整文档上下文，尚未证明多次长片段选择与正式 TSF 路径完全等价。

## 验证

- 小词库测试使用真实核心，覆盖简繁、带声调输入、空输入、非法拼音／长度拒绝、45 个同音词跨页且 ID 不重复、向前返回同一页。
- 全量基础词库运行相同核心查询与服务端组合：两个连接相同身份数字分别输出“中国／中國”，取消后的真实查询结果拒绝；nihaoz 选择“你好”后保留 z，Refresh 携带“你好”上下文，删除到空后上下文清除。
- 四个实际线程各执行 20 轮简繁查询和“你好”查询，共 160 次查询共享同一份核心词库，结果隔离；不是模拟线程编号，也不包含 TSF 插入或认证管道。
- 对简繁、声调、未完成拼音的返回候选逐项对照独立核心会话的 mpn_choose；分页、部分提交和候选消费范围都有真实核心依据。测试不是中文质量评测或性能基准，没有测内存节省量。

## 未接入与下一步

当前只有原生中文拼音查询。Windows 的 WordEvidence SQLite 补词、日语／活用／FF14 主题合并、个人词表、完整快捷键／标点／混打均未迁入，不能把这个适配器替换正式 windowsCandidates 路径。CoreDictionary 没有版本指针或热换词库逻辑；同一服务端会话中途替换词库可能让核心索引失效，因此必须先补词库快照归属和切换边界。

下一步先把真实 Windows 候选合并路径接入独立查询任务，明确 SQLite 连接的线程归属、词库快照寿命、已选片段上下文与分页消费；通过日语／FF14 与基础中文回归后，再优化会话复用与重复解码。认证管道、进程生命周期、全局任务队列／背压、TSF 集成和端到端性能仍待实现。
