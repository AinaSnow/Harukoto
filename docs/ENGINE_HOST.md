后续[受控独立所有者](ENGINE_OWNER.md)可在另一个进程启动和监督本宿主，并验证三个独立查询客户端的退出／重新接入。查询仍直接进入本宿主，控制只转交 Allocate／Inspect；正式常驻和服务发现仍未实现，不改变旧基准的测量范围。

## 启动与生命周期

开发程序接受绝对路径 `--base`、可选 `--themes`／`--personal`，重复的 `--pipe` 指定 1～8 个随机单连接端点；`--ready` 和 `--stop` 是可信启动方显式继承的事件句柄。路径和值由可信启动方选择，不通过管道或注册表自我声明可信。继承句柄在子进程中清除再继承标记。程序不打印输入、词条或异常详情，仅输出固定失败文字和必要的 Win32 数字。

动态模式不传 `--pipe`，改由显式继承的私有映射／事件和 `--connections 1..8` 启动；ready 后允许启动所有者申请新 Listener 或只读检查容量。没有公开控制管道或 PID 发现。上限同时包含监听、已连接和未回收端点；控制接口不承载输入或候选，见[完整契约](ENGINE_CONTROL.md)。

开发测量另支持 `--threads 1..16`（默认 2）和 `--trace` 绝对路径（默认关闭）。开启追踪时先以 CREATE_NEW 创建新文件，拒绝覆盖；有界缓冲区只记固定请求元数据及时间，正常退出后统一写入，不在查询或 I/O 路径写盘。Host 可选 Observer 仅在所属线程成功入回复队列后调用，必须不阻塞、不抛异常、不重入或接触 TSF；缓冲区须活到 run 返回。详细字段、丢失检查及计时成本见[分段测量](ENGINE_IPC_PERFORMANCE.md#可选服务计时与混合负载)，它不是正式持久诊断。

顺序为：生成非零随机引擎运行代次 → 完整验证并加载词库 → 创建工作线程和全部 Listener → 进入 run 后发出 ready。代次不使用可复用的 PID。父进程必须同时等待 ready 和子进程退出，启动失败时不得当作已就绪。客户端继续以 `CreateProcessW` 返回并保留的进程对象认证管道服务端，不能只信数字 PID。

启动方现复用 EngineProcess：使用 STARTUPINFOEX 显式句柄列表，静态模式仅继承 ready／stop 的短期副本，动态模式另加三个私有控制副本；CREATE_NO_WINDOW 隐藏启动并保留 hProcess。挂起创建、加入自有 kill-on-close Job 后再恢复线程；事件循环以绝对期限观察启动／停止，超时终止自己的子进程树，等待实际退出。没有实现正式产品的跨应用常驻代理或自动重启，完整状态和所有权约定见[启动管理](ENGINE_PROCESS.md)。

一个端点只接受一次连接，不复用名称。静态模式在全部端点关闭／监听到期时退出；动态模式回收旧端点后允许分配新名称，空闲时继续等待所有者请求。两种模式都在 stop 事件触发时退出。关闭先撤销连接、取消关联任务和管道 I/O，再 stop／join 执行器，领取并丢弃剩余结果，释放全部通道及所持词库。run 只允许调用一次，返回前在 I/O 所属线程回收 OVERLAPPED。若后端永久不返回，宿主内部 join 仍会等待；外部 EngineProcess 在调用方继续 poll 时可按停止期限终止宿主，所有者放弃或退出时由 Job 关闭保护。正式跨应用所有者寿命、升级策略和未确认选择恢复仍待做。

## 容量与事件循环

| 项目 | 开发程序默认值 | 上限或含义 |
| --- | --- | --- |
| 端点容量 | 静态启动时给出；动态由启动所有者配置 | 1～8，包含 Listener、连接与待回收端点；动态模式回收后可申请新名称 |
| 工作线程／全局任务槽 | 2／32 | Executor 范围为 1～16／1～256；排队、运行、未领取完成共同占槽 |
| 每连接待发回复 | 8 | 配置范围 1～64，含正在写的一帧；超限关闭原连接 |
| 每连接会话 | 64 | 由 ServerConnection 限制，一个会话一个普通在途请求 |
| 监听／单次读 | 30 秒／30 秒 | 固定绝对截止时间；读期限也形成当前实验连接的空闲期限 |
| 写／查询 | 10 秒／10 秒 | 查询从服务端接受时计时，不因排队续期 |
| 终止错误发送宽限 | 1 秒 | 尝试发送 Error 后等待对端断连，最长不超过此期限 |

这些值服务开发验证，不是正式输入法的延迟目标；Host Options 的各时长限制为 1～300,000 毫秒。当前读取单帧最多 64 KiB、单页 16 个候选；输入仍最多 256 字节。主循环每轮处理每端点至多一帧及有界完成邮箱，不在 TSF 线程等待，也不维护无限按键队列。

使用 `WaitForMultipleObjects` 同时等待 stop、完成通知、连接和读写事件，并用最近的读／写／查询／终止截止时间作为等待上限。Executor 新增可选 Wake 回调，在锁内发布结果后通知；Host 仅 SetEvent 到自动复位事件，再在所属线程领取结果。通知可合并，因为每次醒来都会排空有界邮箱；没有逐毫秒轮询，也不需要客户端再发按键来唤醒完成结果。

Wake 回调必须不阻塞、不抛异常、不重入执行器或访问连接／TSF，所用资源必须活到全部线程 join 之后；违反不抛异常约定时终止进程。原有默认构造和条件变量等待仍可使用。`Channel::needsPoll()` 提示同步完成的待领取帧或尚可推进的 I/O，避免完成后没有内核事件而睡到超时。

## 归属、取消和失败

每个 Endpoint 独立拥有 ServerConnection、通道、读写期限和回复队列；所有连接共用同一执行器。宿主先登记精确 Ticket 与 Endpoint 的关联，再提交任务；领取结果后用同一个 Ticket 查回原连接，随后 ServerConnection 再检查当前任务对象，不能仅凭五个相同数字把结果路由到别的连接。

Cancel／Close 先推进服务端状态，再撤销该连接中相应会话的后台任务。断连撤销全部关联任务；取消中的运行任务仍占全局容量，直到实际返回并领取。取消后旧结果直接丢弃，不能修改新组字。已经排队发送的旧回复可能到达，客户端仍必须使用 ClientGate 与候选快照检查归属，不能因为收到管道帧就上屏。

全局容量满时对原任务生成 Overloaded，真实查询异常／坏结果生成 Backend；固定 Error 载荷不包含异常文字。尝试发送终止错误时停止业务处理，保留短暂发送宽限；不保证对端一定收到。查询到期、非法业务、身份冲突或回复容量超限关闭原连接，不伪造成功空候选，也不自动重放 Key／Select。一个连接失败不关闭其他连接。

已关闭连接仍参与取消完成回收，直到其句柄可关闭；不能只跳过它而把未回收的管道一直留着，否则其他连接存活时客户端收不到断连。此缺口由新超时测试复现并修复。宿主没有 TSF PendingDelivery；未来接入时，已确认文字的原上下文归属须继续由客户端保持。
