# 安装、旧进程与词库生效状态诊断

仓库内执行（PowerShell 7）：

~~~powershell
pwsh -NoProfile -File .\Windows\diagnose-ime.ps1
~~~

需要保存给开发者排查时：

~~~powershell
pwsh -NoProfile -File .\Windows\diagnose-ime.ps1 -Json > diagnosis.json
~~~

alpha.21 发行包包含该只读工具。解压 ZIP 后双击根目录 Diagnose.cmd（需要 PS7 在 PATH），或运行 pwsh -NoProfile -File ./diagnose-ime.ps1；安装器解压内容附带的同名入口优先使用随包 PS7。尚未增加开始菜单快捷方式，不需要管理员授权，不自动关闭应用或修改安装、注册表、用户词库。

工具显示安装器记录版本、64 位当前用户／机器 COM 注册、已加载晴词 DLL 的应用、DLL 路径与 SHA256，以及当前用户词库包的版本和启用状态。版本号缺失时保持未知，不从目录名猜测版本；安装器记录可能落后于手工更新，判断是否生效应看注册路径与进程模块。

“一致”表示模块路径当前文件的哈希与注册文件相同，不是对进程内存逐字节校验；安装采用独立版本目录时可用于识别旧模块。“不同，需重启应用”表示两边文件不同：先保存工作，再彻底退出该应用并重开。QQ 等应用要从托盘退出，关聊天窗口可能仍在后台运行。不要为清理旧 DLL 强制结束工作中的应用。

无法枚举、已退出或模块表为空的进程会计入“无法确认”；没有列出旧版不等于全机更新完成。只覆盖 64 位注册，32 位输入应用另行验收。系统组件若仍持有旧模块，可在保存工作后选择注销再登录。

主题磁盘检查读取同一个 CURRENT 快照、包元数据、去重后的启用行数与运行表哈希；行数一致不代表全部内容有效，完整验证仍由词库管理器执行。基础磁盘检查只显示 STATE.json 发布指针，不重新扫描整套词库。磁盘状态本身不能证明已经打开的应用采用了该版本。支持对应版本的接入层可在新组字时热更新词库，首次接入层升级仍需重开应用。

## alpha.21 运行时实例报告

每个加载新版输入服务的应用通过本地共享内存发布诊断记录，按进程创建时间避免 PID 重用混淆；每个进程最多 64 个服务实例，使用线程号和槽位区分。服务退出清除自身槽位，最后一个实例关闭后共享内存释放，不留下磁盘状态文件。读取器只能读取，诊断失败不会阻止输入。

报告显示服务编译版本、实际采用的基础版本与内容标识、主题标识、已准备但未切换的基础标识、最近观察到的加载阶段及上次采用失败标志。服务报告与磁盘指针分别比较，只有基础标识相同才显示“已采用发布版本”；它不表示整个进程的所有实例均完成更新。

| 阶段 | 含义 |
| --- | --- |
| 空闲／上次检查完成 | 最近一次观察时没有待发布结果 |
| 后台检查或加载中 | 后台工作尚未向 TSF 线程交接 |
| 已准备，等待组字边界 | 新结果已准备，但正在组字或有未处理提交 |
| 更新失败，沿用旧版 | 本次加载或应用失败，已采用版本保持 |
| 重载状态不可用 | 服务没有可报告的重载管理器 |

这些是最近实际按键时的观察，不是持续心跳。无状态变化时不重写记录；ObservationAgeSeconds 是距离上次状态变化记录的时间，不是应用失联判断。后台可能已完成但空闲应用尚未再次观察，所以“加载中”持续很久也不能直接判为卡死；在该应用完成／取消组字后再输入并重新诊断。

无共享内存、超出实例容量、记录更新中、权限不足或旧接入层均不报“已更新”。显示安装目录来源时尚无完整内容哈希，不能仅以服务版本推断词库内容。个人表暂不公开内容指纹，主题标识显示但尚未自动比较磁盘主题指针。本工具不是远程监控、认证通道或性能测量器，也不向其他用户会话发送请求。

JSON 报告格式升级为 2，Processes[].Runtime.Instances 包含各实例记录；原有 DLL 比较仍在 Processes[].Status。自动验证覆盖原生发布与 PS7 读取、多实例关闭／复用、并发读写、坏记录拒绝，以及生产服务待切换／已生效／失败的状态边界；真实各应用诊断仍待验收。

JSON 不记录输入文本或应用文档内容，但包含用户名相关路径、应用名和进程编号。提交到公开仓库前应人工删除这些本机信息。升级／UAC 取消／失败恢复／卸载的实机矩阵仍见 [Windows 验收表](WINDOWS_VALIDATION.md)。
