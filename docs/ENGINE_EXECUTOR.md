## 容量和线程归属

构造时明确线程数和任务容量：线程为 1～16、容量为 1～256，线程数不能超过容量；不设置自动产品默认值。槽位一次分配，轮转寻找排队任务，不承诺 FIFO 完成顺序。排队、运行、完成但未领取的任务都占同一容量。领取一个完成结果才释放槽位，调用方领取后自行持有的结果不再属于执行器容量；未来服务宿主仍须限制自己的领取缓存和连接总数。

submit 只接受有效 Key 任务，返回 Accepted／Full／Stopped／Duplicate／Invalid。相同 Ticket 对象在槽位内不会重复接受；不同连接相同数字身份仍是不同任务。不永久保存已经领取的任务记录，重复请求去重由 ServerConnection 管理。

工作线程只读取不可变 Work 和它持有的词库对象。Query 和 Clock 回调必须可并发调用，不能捕获连接、TSF 上下文、COM 或其他线程创建的可变数据库连接。真实适配器仍在查询线程创建、使用和关闭独立 SQLite 连接。执行器不在工作线程调用 ServerConnection，也不直接上屏或更新候选窗口。

每次计算前后检查单调时钟，到期返回 Deadline。默认时钟为 steady_clock 毫秒数；服务端 now／deadline 必须使用同一时间基准。测试可注入确定性时钟。任务在队列中到期后，轮到执行时会跳过查询；不是到期时主动把任务移出队列。连接所属线程仍必须定时 expire，不能等队列腾空才处理超时。

成功结果在存入槽位前校验输入一致性和完整候选编码，包括 UTF-8、消费范围、候选数及 64 KiB 包上限。异常或无效结果成为 Backend，异常文字不会放入协议或日志。异常任务结束后工作线程继续执行其他任务。容量限制的是任务和可交付结果；不能约束 Query 内部临时分配，不能据此宣称解码内存已经优化。

## 所属线程的调用顺序

1. ServerConnection.receive 返回 Scheduled 后，将原 Ticket 传给 submit；Pending／Replay 不再次提交。
2. Accepted 表示等待结果。Full／Stopped 必须分别调用原连接的 fail(ticket, Overloaded／Stopped, now)，发送其错误并关闭传输；不可留着 pending，也不可构造成功的空候选。Duplicate 表示原任务还在执行器中，不再分发；Invalid 表示宿主接线错误，应结束该连接并排查，不重放按键。
3. 所属线程通过 tryTake 领取结果，使用原连接对象路由，调用 Completion.deliver。deliver 将成功结果交给 complete，将错误交给 fail；服务端再次检查精确 Ticket 身份。不能只按载荷里的 connection／session 数字寻找连接。
4. 处理 Cancel／Close 时先让原连接推进组字代次、使旧任务失效，再调用 executor.cancel(oldTicket) 跳过排队计算或抑制运行结果。旧结果仍会被领取并校验，不能发布到新代次。
5. 服务端结果为 Failed 时发送其中的 Error 帧并结束该连接；Closed 表示连接已失效。Rejected／Stale 的旧结果直接丢弃，不去修改其他请求。发送失败也只断开原传输，不自动重放选择。

waitUntilReady／takeUntil 供服务事件循环或测试有期限等待；正式 TSF 所在线程不得调用阻塞等待。当前尚未接入 Windows I/O 唤醒，后续管道宿主需把结果就绪和定时到期纳入事件循环。

## 固定错误格式与连接收尾

Error 帧沿用原请求的五项身份，载荷固定 4 字节：小端 u16 类型号 5，再跟 u16 错误码。基础定义与校验位于 EngineProtocol.h，EngineMessages.h 提供统一 encodePayload／decodePayload 重载。

| 错误码 | 名称 | 含义 |
| --- | --- | --- |
| 1 | Overloaded | 执行器容量已满，任务未提交 |
| 2 | Backend | 查询异常或无效结果 |
| 3 | Deadline | 查询截止时间已到 |
| 4 | Stopped | 执行器停止接受和发布任务 |
| 5 | Cancelled | 执行器已撤销该任务的结果 |

本批这些错误均为终止连接的失败，不是可以原样重试 Key／Select 的提示。正常取消已有 Cancel 回复；Cancel 后对应的 Cancelled 结果通常是 Stale，直接丢弃，不向客户端另发终止错误。

fail 先验证任务是该连接当前在途的同一个对象。复制品、另一连接的任务、已取消任务、已完成任务均不能触发失败收尾，哪怕数字身份相同。当前任务失败则准备 Error，清空全部会话、缓存和内部在途引用，返回 Failed；已经到期时错误码规范为 Deadline。complete 收到当前任务的坏候选也走同一路径，修复此前一直保留 pending 的缺口。分配失败等宿主异常仍须捕获并断开原连接，本批未注入系统分配失败。

ClientGate.accept 在五项身份匹配后还会校验 Error 的固定类型、长度和已知码。空载荷、截断、尾部数据、未知码不会消费合法待回复请求；匹配且合法的错误使整个连接失效，accept 返回 false，绝不能按成功提交处理。传输层仍应关闭发送非法帧的连接，而非无限等待更正。旧错误不能关闭新连接。已经确认的 PendingDelivery 文字继续属于原上下文。

普通请求的语法、身份或会话容量拒绝仍返回内部 Rejected／Reason，尚未为每种拒绝定义可发送的错误；未来宿主必须明确关闭策略。没有可关联任务的握手／非法帧失败也不强行拼造本格式的 Error。

## 停止和资源释放

stop 不等待计算，停止新提交，把排队任务和未领取结果标为 Stopped；运行任务返回后也只产生 Stopped。每个已接受任务保留一个可领取结果，直到领取或执行器销毁。重复 stop 安全，不能重新启动。

join 只能在先 stop 后由所属线程执行，并与其他 join／析构串行；等待所有后端调用返回。析构执行 stop＋join，不分离线程。cancel／超时／stop 都不强杀已运行的核心或 SQLite 调用；若后端永久阻塞，join 也不能返回，后续独立进程看门狗须处理该边界。

任务仍持有快照，停止或连接销毁不能提前释放正在使用的数据。领取结果也持有原任务；最后外部结果／任务引用释放后，旧快照文件保护才解除。
