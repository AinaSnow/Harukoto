# 输入体验检查

2026-11-08。这份记录保留各轮开发时的测量与限制；下文的「尚未安装」指各轮检查当时。修复现收录于 0.4.3 Alpha 1，iOS 0.4.3（43）已安装并启动于开发用真机，尚未完成本版键盘实际输入验收。目标是让喵扑可以安心作为日常主力输入法；目前不能宣称已达到苹果输入法的整体体验。

## 怎样判断有没有变好

| 面向 | 验收方式 | 本轮状态 |
| --- | --- | --- |
| 不丢字、不串字段 | 分段选词、连续删除、切换字段、切换输入法、宿主拒收；核对每次提交及剩余读音 | 补上宿主选区、字段隔离、提交重试回归；仍需各平台真实应用验证 |
| 候选可达、排序合理 | 拼音／注音、繁／简、单字／词／长句；逐键检查而非只看打完后的结果 | 修完整音节证据及分段候选去重；没有按个别词增添例外 |
| 长句不中断 | 只输入下一音节的前半、选句首、继续输入，检查后缀完整保留 | 共用核心回归涵盖中文及拼音中日混打 |
| 手感稳定 | 同机同词库测普通输入和长句的逐键延迟，分开记冷启动、核心计算和画面延迟 | 本轮测主机核心和 Swift 后端；不能代替手机触控到画面的延迟 |
| 画面可读、可操作 | 小屏幕、横屏、最大文字、VoiceOver、降低动态效果／透明度、锁屏恢复 | 自动检查版面尺寸和按键状态；实机视觉与辅助功能尚未验收 |
| 个人词库可靠 | 只学确认的候选，区分繁简及输入模式，编辑或换字段后不学错误相邻词 | 修短期学习边界；Android 和 Windows 仍未有完整同等功能 |

简体拼音使用简体词源的权重。繁体的显示转换不能取代简体的词频和语境。评估时会分开看四种模式，不能以一种模式的结果代表全部。

人工例句只用于发现问题；「指定答案在首屏」不等于输入法准确率。已有开发集与已揭晓的验证集见 [拼音评估](PINYIN_EVALUATION.md)。本轮没有拿已揭晓验证集调参，也没有改词条来迎合它。下一次评估排序质量需另准备未参与调整的材料。

## 第一轮修正

### 共用核心

未完成音节的判定原本只扫桶内前 64 个词条；高频缩写或繁简变体挤在前面时，真实单字读音可能被忽略。现在加载词库时建立完整的单字读音索引，完整拼写检查也共用此索引。这修的是数据查找范围，不是把某几个字的权重拉高。

部分长句候选先按显示文字去重，再计算名额，避免几个繁体变体合并后占掉其他简体候选的位置。同一次按键内重复需要的完整拼音解码结果只计算一次，保留原有搜寻宽度与分数。

### macOS 与共用学习

没有自己的组字范围时不再送出空的 marked text。按 [Apple 的文字输入契约](https://developer.apple.com/documentation/appkit/nstextinputclient/setmarkedtext(_:selectedrange:replacementrange:))，这种调用可能取代宿主目前选中的文字。修正保留取消组字及部分上屏后的后缀更新。

短期相邻词学习现在有明确的终点：切换字段、移动光标、删除已上屏文字、宿主快捷键及中英模式切换。正常的连续中文选词仍可累积个人词组，已保存的记忆不会因切换字段被清除。

### iOS

每次按键、点候选和送出文字前核对文件识别码，不只等待 UIKit 的文字变更回调。新字段会舍弃旧组字的本地状态与临时学习上下文，过期候选点击不会带入新字段；同一字段最初尚未取得识别码的情况则保留组字。这依据 [UITextDocumentProxy 的文件及变更通知](https://developer.apple.com/documentation/uikit/handling-text-interactions-in-custom-keyboards)处理；识别码暂时不可用时仍有宿主兼容性边界，不能宣称涵盖所有应用。

返回键标签及语言未改变时不重复更新。旋转或挂载期间候选区短暂为零宽时，不再因同时保留日语候选而计算出负宽度。

### Android 与 Windows

Android 已从核心取出的文字，在目前编辑阶段保留到宿主接受为止；拒收时显示重试，不先把后缀写到前缀之前。更换字段或结束编辑时清除待送内容，避免跨字段泄漏。这是暂时拒收的保护，不是应用关闭后的文字复原功能。

Windows 的 TSF 键盘处理加入左右 Windows 键检查，把系统快捷键交回系统。

## 第二轮：光标语境、记忆与平台状态

macOS／iOS 开始一段中文组字时，将光标前最多四个连续汉字送入现有的语境排序；拼音、注音、简繁共用这条路径。macOS 仅查询前八个 UTF-16 单位，拒绝选区、无效位置、不完整回复及系统保密输入状态。iOS 使用系统提供的 `documentContextBeforeInput` 片段，再取相同的汉字后缀。两边都不跨标点、空白、英文、emoji 或换行，不取光标后文，不保存宿主前文；查不到就维持原排序。

只有开始读音的按键会查询；组字中的按键、空闲删除、空格不反复向宿主要文字。部分选词和删改读音沿用同段语境；下一次开始组字重新取得当前字段的数据。这是既有词库语境分数的接入，不是语意模型，也不等于任何句子都能选对。

个人词库的「忘记」现在一并删除该读音的上下文记录；「清除」立即持久化，避免关闭程序后旧快照复活。开关记忆、清除及忘记会使临时学习上下文失效。加载时限制记录数、清除无效值与重复，防止异常使用次数溢位；损坏文件不再被普通 `flush()` 覆盖。一般学习仍延迟写入，没有改成每键写磁碟。

第二轮整合结果：macOS 789 项 smoke 通过，包括上下文传递、删改读音、选词消耗、空语境回退与记忆隔离；iOS 模拟器编译和 8 组逻辑测试通过。尚未安装到日常使用的输入法或 iPhone。这些是程序与模型测试，不是宿主兼容性、真机触控延迟或 Apple 输入法对照测试。

Windows 接入 TSF 字段移除通知，释放已关闭字段的会话及引用；字段关闭或服务停用后，晚到的异步提交不再执行。正常切换焦点仍保留各字段的组字，没有强行提交或按容量淘汰。队列测试含晚到回调与跨字段隔离，普通执行及 AddressSanitizer／UndefinedBehaviorSanitizer 通过，x64 DLL 交叉编译通过；TSF 实际事件投递仍待 Windows 验证。

Android 移除固定 312 dp 最低高度与垂直置中，依目前窗口、安全区、列数与高度偏好排版。一般拼音内容自然高度为 268 dp；小窗口可收至 230 dp，注音为 274 dp，另加系统安全区。按键列与候选条维持至少 44 dp 纵向点击范围，展开候选不改变键盘总高。192 组几何测试及 API 35 Java 编译通过；极矮窗口低于几何下限仍需更大的编辑空间，未完成实机验收。

## 第三轮：连续输入与候选稳定性

个人记忆原本会触发整排候选按单字词频重新排序，抵消前文带来的次序；即使记忆中的词已不在候选里，也会重排其他字。修正后只允许有实际记忆加分的候选向前移，保留其余候选的相对次序与跨语言位置。新增拼音／注音、简繁的回归，检查旧词已失效、强化原首选、重复刷新及实际提交的文字；修改前可重现 15 个失败断言，修改后全部通过。没有为例句改词频。

核心修正单字后备候选的切段边界：不得在声调或明示分隔符前截断，避免选词后留下孤立声调。`Core/tests/check_composition_state.py` 使用生成词库及固定随机数种子，涵盖拼音／注音、繁简、普通／Android 完整候选模式，共 12,044 次操作、15,854 次状态检查；438 次选词中有 291 次部分选词。核对剩余读音、候选 metadata、上屏队列、退格、取消、翻页、切换字形及容量边界。修改前同一测试会在候选留下孤立声调时失败。这是状态正确性测试，不是自然语言排序准确率。

iOS 的长按删除与空格光标手势在字段切换、键盘隐藏或场景失去活跃时取消；迟到的放手或移动回调不再补打一个空格或删到新字段。手势 driver 增加取消、重复放手、迟到开始、无效坐标与取消后恢复的测试。

Android 将成功上屏引发的延迟／合并通知与外部光标操作分开处理。宿主取消组字、清空或粘贴后，不再沿用旧读音。待送文字期间若光标移动，暂停自动重试，用户点提示后才送到目前位置；若宿主拒绝结束旧组字区，先保留文字，不直接覆盖。长按动作在键盘隐藏、结束输入、重建及移除视图时取消。模型只保留最近 32 次成功写入的位置预期；异常宿主的更长延迟或非标准回调仍需真机排查。

第三轮验证：macOS 837 项 smoke 通过；普通拼音主机逐键计算 median 0.20 ms、P95 0.63 ms。iOS 模拟器编译与 8 组逻辑测试通过。核心状态测试及相邻的长句、混打、容量、单字及 C ABI 回归通过。Android API 35 Java 编译、选区通知、暂停提交、192 组版面与既有候选测试通过。手机手势尚未实机验证，程序也尚未安装或发布。

## 第四轮：完成文字的交付与失焦恢复

共享 Engine 原本在切换输入方式时，连同尚未送出的完成文字一起清除。macOS 试打页的「完成组字 → 切换模式」可稳定重现；拼音、注音与繁简共八个失败断言。现在成功切换引擎后保留待送文字，连续切换仍只取出一次；试打页点选候选或切换模式后也会送出，不必等待下一次按键。没有改变取消组字或由宿主决定何时完成组字的规则。

iOS 暂时取不到已知文件的识别信息时，保留已选前缀、未完成读音与待送文字，暂停写入和手势。同一文件恢复后续接，确认换到另一文件才清除旧的本地状态。设置中的模式切换也延后到文件可确认时。这是本地状态机修复；系统没有提供 marked range 查询或写入回执，锁屏后宿主是否保留原组字区仍要真机跨 App 验证。

Windows 现在暂停失焦字段的交付队列，晚到的 TSF 编辑回调不会立即写入；返回原字段并收到可处理的按键后重试。选词清空读音但文字尚未上屏时，后续数字、空格会跟在队列后方，避免先于中文出现。Enter、删除、光标等直接交宿主的命令，仍未全面纳入同一顺序机制。

核心状态测试新增声调、无调和明示分隔符交错的情况，11,323 次操作、15,114 次检查及 288 次部分选词通过。另修正混日总分的 `int` 溢位：合法的极端自定义权重原本会触发 UBSan，改用 64 位累加后通过，正常排序公式未变。它不是常用词排序质量的提升。

macOS 完整构建和 855 项 smoke 通过，普通拼音主机逐键计算 median 0.21 ms、P95 0.62 ms。iOS 模拟器编译与 8 组逻辑测试通过。Windows 队列、标点与实际核心部分选词测试、x64 DLL 交叉编译通过。这轮没有重装使用中的输入法或发布安装包；iOS 锁屏恢复及 Windows 宿主互动尚无本轮真机验证。

## 第五轮：长句前段与个人排序

这轮没有补例句词条、调整个别词频或扩大搜寻 beam。修正核心的两个通用条件：较短整词已出现时，仍可在它之后搜寻更长的完整前段；上下文加分只比较读音消耗范围相同的候选，避免把短前段推到既有完整长句之前。合成词库的长前段首屏检查由 0/24 改为 24/24，拼音／注音、繁简的完整长句顺位检查由 0/4 改为 4/4。这些是根因回归，不是自然语言命中率。

拼音下一个词还未打完时，也沿用既有分段器列出已完成前段中的较早切点。分段最多三个，先保留不同切点，再以空位保留同切点的次选，不增加 beam 或为次选另做解码。合成词库早期分段检查 0/24 → 24/24；已知的 `wobayaos`、`wobayaosh`、`qingbachuangh`、`bagangcaidewenj` 在繁简下共八项首屏检查通过。84 次选词／续打确认尾音和提交文字正确。

macOS／iOS 的共享记忆层不再排除超过八字的完整中文句子。测试实际选取非首位长句两次，再次输入时可前移；保留核心原有来源、索引和消耗信息，不把同文短前段当成完整句子。拼音／注音、繁简共 36 项新检查，修前四项排序失败，修后通过；忘记记录后恢复原排序。既有保存上限及至少两次选取的门槛不变。

新增 `Core/tests/check_long_sentence_holdout.py` 逐键诊断 12 组日常组合句，对照无声调简体拼音和带声调注音。这是本轮整理的回归材料，并非独立受试者语料；工具区分词库可分解性、目标顺位、前段消失与选取契约。只有提交或剩余读音违反契约才视为硬失败，语义缺口会完整保留在报告中。

同一批逐键诊断中，拼音曾失去指定正确前段的句子由 10/12 降至 6/12，注音仍为 3/12。这个指标观察整个候选池，不要求所有早期切点永远保留，因此用来定位缺口，不单独作为质量分数。完整目标前五命中维持拼音 8/12、注音 12/12；拼音仍有三句指定完整文字未出现，虽然都能由词库分解。两种模式各 36 次部分选词与续打通过。旧版 36 题 validation 的分组名次统计未变，未将这些已看过的题目声称为新验证集。

固定长句基准单次同机 P95：自然长句 6.881 → 6.890 ms、重复音节 10.968 → 11.038 ms，约持平；不是提速结论或手机端到端延迟。核心相邻回归与 11,323 次状态操作通过。

最终 macOS 完整构建及 891 项 smoke、iOS 模拟器编译和 8 组逻辑测试通过。本轮未替换使用中的系统版、未安装 iPhone 或发布。诊断快照保存在 `.build/long-sentence-progression-round5-before.json` 和 `.build/long-sentence-progression-round5-after.json`；它们包含核心与词库校验值，供下一轮比较。

## 第六轮：同音前段的保留与搜寻成本

拼音与注音原本在某些切点只留下第一种解读。下一个音节出现后，原本可选的正确同音前段会从整个候选池消失。现在重用同一次解码的其他结果：拼音最多补六个同音前段，注音在最近有效切点最多补两个。原有切点优先，拼音额外选项接在原候选后方，避免推迟已存在的完整句。未加历史候选缓存，改声调、退格重打及新组字仍由目前读音重新计算。

`check_prefix_continuity.py` 涵盖 12 条拼音／注音、繁简逐键路径和合成词库；修前 14 处候选消失，修后全可选，其中六条实际路径的最终目标位于前七。选取后保留精确尾音，改声调不保留旧候选。另用五条完整句、同一切点多个同音词的合成数据，确认额外分段不挤走完整句的原有位置。macOS／iOS 共用 Engine 的六条注音回归也检查了前段上屏及尾音续打。

新增并冻结 20 组日常句子（`Core/tests/data/long-sentence-round6.tsv`），与上一轮 12 句不同，全文未出现在三份本地人工覆盖表。它仍是开发时整理的材料，不是受试者语料或使用准确率。基线源码、工具、词库及题目校验值保存在 `.build/long-sentence-round6-freeze/`。最终结果：

| 同一批 20 组诊断 | 拼音修前 → 修后 | 注音修前 → 修后 |
| --- | ---: | ---: |
| 曾失去指定正确前段的句子 | 14 → 9 | 5 → 1 |
| 按指定目标贪婪分段可完成 | 12 → 14 | 19 → 19 |
| 完整目标位于前五 | 9 → 9 | 18 → 18 |
| 完整目标可找到 | 11 → 11 | 19 → 19 |
| 部分选取及续打契约通过 | 60 → 60 | 60 → 60 |

最终 40 组完整目标的名次与基线相同。分段成本由工具在知道目标的前提下，于完整输入后反复选最长正确前段；这不是最优策略，也不等于真人按键成本。报告为 `.build/long-sentence-round6-baseline.json` 与 `.build/long-sentence-round6-final.json`。

整句搜寻的缺口尚未解决。诊断发现同音词先按静态频率截前五，再计上下文分，有搭配证据的后续词可能过早出局。`check_sentence_search.py` 默认会明示已知缺口；加 `--require-context-search` 可将它作为失败检查，不能把默认成功退出说成缺口已修复。

本轮评估但未合入的方案包括后缀多样性、上界搜寻及查询内缓存；它们有质量或耗时退步。明示把词候选预算改为六、输出路径仍为五的方案，虽通过合成根因测试，旧题集和新 20 题均未见实际收益，压力输入 P95 却增加约 17%，因此也未合入。词库、词频及原有搜寻预算未变。

最终分段修正同机交错三轮测量，P95 中位数：自然长句 6.881 → 6.938 ms，重复音节 10.990 → 11.005 ms。这是本机核心耗时，没有包含手机、宿主编辑或窗口绘制。

最终 macOS 构建及 915 项 smoke、iOS 模拟器编译及 8 组逻辑测试通过；核心 11,323 次状态操作、前段／声调／上下文回归通过。旧 validation 的逐题顺位未变。本轮没有替换日常使用的系统输入法，也没有真机安装或发布。

## 仍需完成的体验差距

| 优先顺序 | 差距 | 下一步验收 |
| --- | --- | --- |
| 1 | macOS／iOS 已接入短左语境，但没有右语境或完整语意模型 | 真实应用测移动光标、粘贴、删改及换字段；独立评估排序是否减少修改 |
| 1 | 尚无完整的读音中段编辑与已上屏文字重新选词 | 保持候选与原始读音位置对应；测中文、emoji 及混合字符串，不以重新输入整句代替 |

| 2 | 长句排序尚无代表真实使用分布的独立评测 | 固定新测试集，以完成一句所需选词／改字次数对照 Apple，并记录逐键候选变化 |
| 2 | 缺同机 Apple 输入法的端到端操作对照、实机内存及掉帧结果 | 在隔离文字框测试，不打断日常输入；测冷启动、长时间打字、横屏与辅助功能 |
