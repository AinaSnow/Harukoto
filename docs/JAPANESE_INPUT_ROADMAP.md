# Windows 日语辅助输入

全项目进度、构建验证与接手顺序见[开发状态](DEVELOPMENT_STATUS.md)。第一阶段已实现；第二阶段已接入活用面板首版，仅支持整段触发词，尚待实机验收；第三、第四阶段及第五阶段的生词本为规划，主题包管理已实现。每阶段按“核心实现→测试→Windows 交互→实机验收”推进。

参考 [Madamada 产品说明](https://madamada.catchingnow.com/llms.txt) 和[公开自定义词表格式](https://madamada.catchingnow.com/help/custom-dictionary.md)，在晴词内独立实现。上述页面没有提供可直接接入的引擎 SDK 或源码；本实现不包含其内置词库，不代表与该产品官方集成。

## 第一阶段：显式触发词与读音

已实现 Windows TSF 侧的单词候选、假名读音标注和本地词表导入。基础词表独立整理了 41 组触发词，沿用原有日语罗马字词库。简洁版候选窗不再显示猫爪，上方小字显示读音及「拼」或「EN」标记。同形中文与日语候选分开保留。

| 输入 | 日语候选 | 读音 |
| --- | --- | --- |
| `riben` | 日本 | にほん |
| `tushuguan` | 図書館 | としょかん |
| `jiankangbaoxian` | 健康保険 | けんこうほけん |
| `coffee` | コーヒー | こーひー |
| `schedule` | スケジュール | すけじゅーる |
| `pointcard` | ポイントカード | ぽいんとかーど |
| `xingbaogu` | エリンギ | えりんぎ（并显示杏鲍菇） |

数字键选择，F4 展开本页其他日语候选；英文触发时也保留英文原文候选。空格仍输出原始拼音／字母加空格，Enter 确认高亮候选。

### 自定义词表

保存 UTF-8 文本，例如：

```text
# 我的日语词表
店長 | てんちょう | pinyin: dianzhang
ポイントカード | english: point card
エリンギ | chinese: 杏鲍菇 | pinyin: xingbaogu
```

在仓库根目录执行：

```powershell
python Windows/import-japanese-dictionary.py C:/path/to/words.txt --check
python Windows/import-japanese-dictionary.py C:/path/to/words.txt
```

编译结果写入 `%LOCALAPPDATA%/Meowpuut/japanese-custom.tsv`，无需管理员权限。此旧入口会替换当前用户的一个自定义词表；需要多个主题独立启停和回退时，使用新增的[主题包管理](DICTIONARY_PACKAGES.md)。两种入口可共存。校验失败时不会覆盖旧文件。重新打开使用输入法的应用后加载新词表。也可用 `--output` 导出到指定文件。

支持 `pinyin`、`english`、`chinese`、`priority`，以及同字形多读音。`pinyin`、`english` 可重复；全角分隔符、拼音声调符号、空格、连字符会规范化。含汉字的词须显式填写平假名读音；alpha.9 起可用 - 表示没有可靠读音，仅输出表记。未知属性忽略；`pos` 校验合法性，但本阶段不产生语法变形。仅有读音而没有显式触发词的自定义行不会加入索引。全部转换在本地完成。

这只是公开格式的一个子集，不是完整兼容实现。第一阶段没有任意中文翻译、自动推导所有日文汉字拼音、80 万日语词库、自动罗马字索引或完整日语整句解码。显式触发词只匹配整个输入，避免误伤中文长句排序。

## 第二阶段：动词与形容词变形

JP-02 的编译和辅助数据加载已完成，JP-03 已接入 F6 活用面板首版。输入 chi、xie、qu、lai、xuexi 等触发词，使用方向键高亮对应日语词，出现“F6 活用”后按 F6 进入。面板显示读音和形式标签；数字 1–7 或 Enter 选词，Page Up／Page Down 翻页，F6／Esc／退格返回原候选页和高亮。

首版限定整段精确匹配，不对混合长句的局部候选做活用。返回后原始组字不变；继续输入字母会返回正常候选并追加字母；空格保留既有原始输入加空格行为。F4 在普通候选中仍用于展开，在活用面板中不折叠形式。切换输入上下文时退出活用面板。

独立词表含十条基础示例，详见 [格式说明](JAPANESE_CONJUGATION_FORMAT.md)。原型覆盖一段、五段、する、来る及两类形容词和显式例外，不代表完整日语形态分析。组字中途的部分活用、更多例外及实机应用兼容性继续验证。

## 第三阶段：敬语与常用表达

加入普通／丁宁／尊敬／谦让切换，显式维护「行く」「食べる」「見る」等专门敬语。人称、亲属、公司、寒暄另建表达表；不能通过统一字符串替换假装语境正确。提供原词、读音、礼貌层级和用法提示。

## 第四阶段：日语整句与混打

为拼音、英语、罗马字建立共同分段和读音消耗模型，支持部分选词、活用形直接输入、未完成末词补全及前后文排序。以 `tianqigaii`、`coffeewonomitai` 等作为功能验收示例，同时用独立材料评估中文排序、日语自然度与逐键延迟。现有中日混打不足以代表该阶段完成。

## 第五阶段：生词本和词库管理

0.4.4-alpha.6 已实现主题包图形与命令行首版：预览、跨包冲突诊断、独立启停、更新、上一版回退及 TSF 加载。窗口显示来源和许可，已接开始菜单及设置入口。基础词库冲突诊断、候选来源标记和生词本未实现，详见[主题包说明](DICTIONARY_PACKAGES.md)。FF14 审核与导出工具已实现，当前 0.3.0 全量包含 57,672 条来源记录、113,463 组触发，逐条核查与程序对齐分别记录，详见 [FF14 全量说明](FF14_FULL_DICTIONARY.md)。

提供本地词库启停、导入诊断、生词读音记录、复习状态、CSV 导出及记忆开关。学习记录只来自用户确认的候选，并可查看、停用和清除。主题词库按来源与授权分别管理；同步另行设计。
