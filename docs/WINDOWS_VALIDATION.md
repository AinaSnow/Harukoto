# 独立引擎开关实机清单（WIN-03 第 6 步，下一个试用包起，待执行）

目的：确认打开实验开关后打字结果与关闭时相同，引擎能按需启动、跟随词库更新、出问题时自动回到输入法自己计算。每项记录“通过／不通过／现象”，不必记录输入内容以外的隐私。

准备

1. 安装新试用包，安装日志里应有 `Engine release approved: …`；若出现 `Engine release metadata was not updated`，记下警告全文后停止本清单。
2. 运行 Diagnose.cmd，确认“独立引擎开关：关闭（默认）”。
3. 按[操作指南](USER_GUIDE.md)“独立引擎”一节打开开关（DWORD `StandaloneEngine`=1）。

记事本（普通应用）

4. 打开记事本，输入 `nihao`，空格上屏；再输入 `zhongguorenmin`，用数字键分两段选（先选一个短词，再选剩余部分）。现象应与关闭开关时相同；第一次打字的约 2 秒内可能仍由输入法自己计算。
5. 运行 Diagnose.cmd：“常驻引擎”应为“就绪”，记事本实例的 Engine 行应为“独立引擎”，原因 `none`。
6. 依次试：`vrq`（日期）、`v123`（数字）、`taberu` 后按 F6、`zhongguo` 后按 `]`、对学到的词按 Ctrl+Delete、PageDown 翻到第 3 页。每项与关闭开关时的结果对比。
7. 选一个第 3 个候选上屏，再输入同样的拼音：所选词应排到前面（学习生效）。

QQ 或其他聊天应用

8. 同时开着记事本和 QQ，两边交替各打几句。Diagnose.cmd 中两个进程的 Engine 行都应为“独立引擎”，“常驻引擎”的接入方应为 2。

FF14（或其他游戏，UI-less）

9. 在游戏聊天框输入几句中文（含分段选词）。候选应在游戏自己的候选界面里出现，没有延迟感；Diagnose.cmd 中游戏实例 CandidateUi 为“应用自绘”时 Engine 行也应为“独立引擎”。若游戏以管理员身份运行，Engine 行为进程内属于预期。

更新与回退

10. 用 Dictionaries.cmd 启用或停用一个主题包、或发布一个基础词库快照，在记事本里结束当前组字后继续打字：几秒内 Engine 行应恢复为“独立引擎”（中间短暂出现 `identity` 属于预期）。
11. 在任务管理器结束 `harukoto_engine_host.exe`：继续打字不应丢字，Engine 行出现 `unavailable`／`fallback` 后过一会儿恢复。
12. 关闭开关（`StandaloneEngine`=0）后打字恢复原样，Engine 行为“关闭（进程内）”。

需要反馈

- 任何与关闭开关时不同的候选或上屏结果（输入的拼音、期望与实际）。
- Diagnose.cmd 中“常驻引擎”一行与各实例 Engine 行的原文。
- 明显的延迟、卡顿或候选窗闪烁出现在哪个应用。
