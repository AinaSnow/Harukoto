## 编码与范围

载荷以小端 u16 类型开头，后续整数仍为小端。字符串先写 u16 字节长度，再写原始 UTF-8，不带结尾 NUL；解析必须恰好消费全部字节。坏包、截断、额外尾部、非法长度或字段值不覆盖调用者的输出对象。整个载荷受 64 KiB 上限约束，候选总编码超过上限会拒绝，不能静默截词。

| 类型 | 字段顺序（类型号之后） | 说明 |
| --- | --- | --- |
| Key=1 | action:u8、text:u8、simplified:u8 | action 为 Text=1、Backspace=2、PageNext=3、PagePrevious=4、Refresh=5；简体标志只能为 0／1 |
| Candidates=2 | input:string、more:u8、count:u16、候选数组 | more 只能为 0／1；每项为 id:u64、consumed:u32、text:string、reading:string |
| Select=3 | sourceRequest:u64、candidate:u64 | 引用候选回复的请求号和候选 ID，两项非零 |
| Commit=4 | sourceRequest:u64、candidate:u64、consumed:u32、text:string、remaining:string | 回复原 Select 请求，原协议头五项身份必须一致 |

本批规范化输入仅含小写 a～z、0～9、单引号，最长 256 字节；消费范围以该 ASCII 输入的前缀字节数计算，不按中文／日文文字长度计算。Text 只携带一个此范围内字节，其他 action 的 text 必须为 0。尚未定义原始虚拟键、修饰键、标点、直接 Unicode 输入和全部快捷键路由，不能据此覆盖现有输入法所有行为。

候选正文非空，正文／读音各最多 1,024 UTF-8 字节；读音可空。UTF-8 必须是合法 Unicode 标量，拒绝过长编码、孤立续字节、代理项、超过 U+10FFFF、截断及 NUL／C0／C1 控制字符。候选 ID 在同一份结果内必须唯一且非零，consumed 必须在 1～输入长度之间。

单包最多 128 个候选，这是传输批次上限，不是输入法候选总数上限。more 表示还有后续批次；空列表不能标记 more。真正的分页游标、稳定追加和引擎搜索预算尚待服务端实现。每个新回复都有新的 sourceRequest，旧显示列表上的选择不可拿到新列表里执行。

## 选词与部分提交

CandidateSnapshot 为每个上下文单独保存候选、来源身份和最新请求号。publish 只接受合法 Candidates 回复，已绑定后不允许换到其他连接／引擎／会话，也拒绝旧组字代次、重复或倒退的请求号。连接重建时必须创建新快照对象。

Select 必须匹配原连接、引擎、会话、组字，自己的请求号必须晚于候选请求号；载荷 sourceRequest 必须等于当前候选版本，candidate 必须存在。不用候选数组下标作为跨版本身份。“日本”和“にほん”作为两个 ID 分别选择，即使读音相同也不能互相代替。

preview 只计算预期结果，不执行引擎：提交正文来自原候选，消费长度来自该候选，remaining 必须等于原 input 去掉所消费前缀后的精确后缀。例如 ribennihao 选择消费 5 字节的“日本”，提交“日本”并剩余 nihao。不能接受服务端擅自替换文字、改变消费范围、丢弃或增加后续拼音。

validateConfirmation 是纯校验；confirm 再校验一次后使整份候选失效，保留最后请求号。重复回复不可再次确认。部分提交后组字代次保持不变，通过后续 Refresh 请求取得 remaining 对应的新候选版本；Refresh 不应输入字符或重放上一次选择。该调度及真实核心操作尚未实现。

新按键、取消、关闭或断连时，调用方应立即 invalidate 旧候选可选状态；invalidate 保留请求号，防止重发相同旧结果。它不能替代 ClientGate 对晚到在途请求和连接状态的判断，也不会自行改引擎状态或本地上屏队列。

## 与 ClientGate 组合

两者必须在同一所属线程协调，任何一个单独成功都不等于允许上屏。推荐顺序已经由组合测试覆盖：

1. 保存原请求类型、Select 的完整帧和对应上下文，不从当前焦点猜测归属。Candidates 只可作为约定的 Key 回复，Commit 只可作为 Select 回复；通用 ClientGate 不负责识别业务类型。
2. 候选回复先复制 CandidateSnapshot 到临时对象并调用 publish；校验成功后再让 ClientGate.accept 消费对应请求，最后替换正式快照。坏载荷不能消耗合法的待回复状态。
3. 提交回复先 validateConfirmation，再 ClientGate.accept，最后 confirm 使候选失效；只有全部成功才将经过验证的 UTF-8 文本转换后追加到原 PendingDelivery。正式接入仍须处理分配失败／转换失败等交付路径。
4. 过期、错误或不属于当前请求的回复不能提交。断连不清掉已确认并存入原上下文的文字；队列暂停、恢复和关闭继续由原上下文生命周期管理。

服务端必须另行验证认证连接、会话状态和执行顺序；本类的 resolve／preview 不是服务端调度器，也不提供执行后去重日志。选词已执行但客户端没有收到回复时如何恢复，仍待协议设计，不自动重发可能重复上屏的操作。
