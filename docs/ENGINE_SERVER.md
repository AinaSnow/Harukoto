# 引擎服务端会话调度原型

WIN-03b 第三批，2026-11-10。Windows/EngineServer.h 新增 ServerConnection，把[协议](ENGINE_PROTOCOL.md)和[候选消息](ENGINE_MESSAGES.md)接入服务端状态模型。现有输入法运行时、alpha.22 安装包及本机配置没有变化。

当前实现接收请求、保存各会话规范化输入、分发不可变任务、校验完成结果、更新候选和选词去重。测试用固定候选生成器，并没有调用真实核心，也没有线程池、网络／管道、认证或独立引擎进程。所谓“调度”是任务接受与完成的状态管理，不是已启动后台服务。

## 连接与会话

每个已认证的传输连接必须有一个独立 ServerConnection，所有方法在同一所属线程调用。外部输入里的 connection 数字不能作为全局查表依据；不同客户端可使用相同 connection／session 数字，其状态仍由不同对象持有。构造时传入非零 engine 运行代次，生成与身份认证由后续进程／传输层实现。

Hello 载荷必须为空，第一次成功后固定连接身份并回复 HelloAck。Open 要求空载荷、composition=1、递增的新 session 编号；每连接最多 64 个会话，关闭后不复用编号。会话分别保存输入、候选版本、组字代次和至多一个在途查询。

新请求号在整个连接内递增，跨会话也共享这一规则；服务端收到请求有序，任务完成可乱序。同编号不同内容、错误身份、旧组字或不存在的会话会被拒绝，不执行部分操作。当前 Open 尚无片段上下文载荷；每个 Key 自带简繁标志并传入任务，未实现所有系统按键语义。

## 查询任务与取消

Key 校验通过后，基于当前输入准备副本：Text 追加一个规范化字符，Backspace 删除末尾一个字符，Refresh／PageNext／PagePrevious 保持输入。当前输入最长 256 字节，分页只转交 action，尚无分页游标或真实搜索实现。此时旧候选失去可选资格，返回 Scheduled 及不可变 Work。

Work 携带原请求、输入副本、KeyMessage 和服务端截止时间。后台必须只处理该副本和只读数据，不能持有或修改 ServerConnection、客户端对象、COM 或原会话的可变核心状态。完成后将 Work 和 CandidatePage 交回所属线程调用 complete：

- 必须是该会话当前持有的同一个任务对象；即使五项数字身份完全相同，其他连接的 Work 或复制品也不能完成当前请求。
- 返回页必须通过原有消息校验，input 必须与任务输入完全相同。失败不改变正式输入／候选，也不产生成功回复；任务保持待完成直到被取消、断连或超时。
- 结果与缓存准备成功后，才将输入／候选一次性切换并释放在途任务。较早任务的完成不会降低连接已经见过的最大请求号。

Cancel／Close 可以越过本会话的在途查询，但需要更高 composition。Cancel 清空输入、使候选失效并释放在途引用；Close 移除会话。两者都移除该会话旧的缓存回复，保留本次控制回复供重复请求确认。它们不会强制终止已经运行的计算，但旧任务之后的 complete 不再有修改状态或返回文字的资格。

每个连接最多保留 64 个尚有引用的 Work，包括已取消但仍被执行器持有的任务；达到上限不接收新的 Key，旧引用释放后才能继续。该限制防止同一连接靠反复取消无限生成任务，但不代替全局连接数、线程池及队列的上限；全局背压仍需实现。

## 选词与重复请求

Select 必须引用当前候选版本和候选 ID，并匹配本会话与组字。服务端通过 CandidateSnapshot.preview 计算提交文本及精确剩余拼音，先准备回复和缓存，再更新本会话输入并使旧候选失效。这是原型输入状态变化；尚未调用核心的选择／学习／上下文更新函数。

每连接保存最近最多 64 个完成回复，内容包括原请求和原回复。相同请求重达时：

| 情况 | 行为 |
| --- | --- |
| 同一个请求仍在途 | 返回 Pending，不再次交出任务 |
| 请求完全相同且回复仍在缓存 | 返回 Replay 和原回复，不再次修改输入 |
| 相同请求号但内容、类型或身份不同 | Conflict，拒绝 |
| 已从缓存淘汰或被取消／关闭清理的旧请求 | Stale，拒绝，不重执行 |

缓存不是持久日志，不支持跨连接恢复，也不是服务端主动重发策略。现有 ClientGate 对同一回复只接受一次，所以 Replay 不能再次写入本地队列。测试确认多次重复 Select 后剩余拼音仍只被消费一次；取消后即使旧 Select 重达，也不能再取出旧提交回复。

## 超时、断连和交付边界

时间来自调用方同一个单调时钟；Key 的 deadline 必须大于 now。任一在途任务到期，expire 关闭整条连接并清除会话、缓存和内部任务引用。receive／complete 也检查到期；没有请求时仍需要外部定时调用 expire。本类没有握手计时器、进程看门狗或任务强杀。

disconnect 是终态，不能在原对象上重新握手；新传输创建新对象。外部仍持有的旧 Work 可以完成自己的计算，但新对象不会接受它；不会恢复旧输入或重放选词。已经被客户端确认并保存于原 PendingDelivery 的文字由该上下文继续管理，服务端不接触它。

Result 的 Reply／Replay／Scheduled／Pending／Rejected／Closed 以及 Reason 是进程内部状态，不是已经定稿的网络错误协议。未来传输必须明确拒绝后的 Error 或断开策略，不能伪造空成功回复。分配失败等异常需由服务宿主捕获并安全关闭连接；尚未做故障分配器注入。跨断连的“选词已执行、客户端未收到”仍存在结果不确定性，本批不承诺无损恢复或恰好一次上屏。
