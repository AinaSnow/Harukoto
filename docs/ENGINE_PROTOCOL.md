## 已实现的消息格式

整数固定小端，逐字节读写，不传输 C++ 结构体、指针、HWND 或 COM 地址。头长 56 字节，载荷最多 65,536 字节。版本、消息类型、保留位、长度和身份组合不合法时拒绝；不按未校验长度分配。数据不足返回 Incomplete，完整返回 consumed，允许传输层按 consumed 拆分粘连消息。输出对象只在完整有效时替换。

| 偏移／长度（字节） | 字段 | 约束 |
| --- | --- | --- |
| 0／4 | magic | ASCII HKIP |
| 4／2 | version | 必须为 1，不自动降级解释 |
| 6／2 | kind | Hello=1、HelloAck=2、Open=3、Key=4、Select=5、Cancel=6、Close=7、Reply=8、Error=9 |
| 8／4 | payload_length | 0～65,536 |
| 12／4 | reserved | 必须为 0 |
| 16／8 | connection | 客户端连接代次，非零 |
| 24／8 | engine | 服务端运行代次；Hello 必须为 0，其他消息非零 |
| 32／8 | session | 当前连接内的上下文编号；握手为 0，其他消息非零 |
| 40／8 | composition | 会话的组字代次；握手为 0，其他消息非零 |
| 48／8 | request | 单个 ClientGate 生命周期中递增的请求号，非零 |
| 56／可变 | payload | 本批作为不透明字节，仅握手及 Open／Cancel／Close 成功回复要求空载荷 |

身份数字用于响应匹配，不是身份认证或访问凭证。两个客户端可以有相同数字；未来服务端必须先按已认证的连接对象隔离，再用 session 查找，禁止全局仅按 session 索引。engine 运行代次必须由将来的服务端生成，不能用可能复用的进程 ID 替代。不同传输连接的读取回调必须绑定对应 ClientGate，不能把销毁后残留的响应投递给新建 gate。

解码器不持有接收缓冲区、不执行 I/O；未来传输必须对缓冲总长和等待半包时间设上限，循环拆帧并先校验类型化载荷，再调用归属检查。遇到非法帧应断开该传输，不扫描魔数后继续猜测边界。尚未实现 Key、候选、Select、提交文本或错误码的业务格式，因此不能直接把本批 Reply 的 payload 当成可上屏文字。

## 客户端状态与归属

ClientGate 只能在一个所属线程使用，禁止复制／移动。它不持有 TSF 对象，不等待后台、不创建线程，也不操作 PendingDelivery。未来异步 I/O 的完成事件需投递回所属线程处理。

1. connect 清除旧会话，递增 connection，生成 Hello。HelloAck 必须匹配连接和请求号，且携带非零 engine；匹配成功才可创建会话。重连不清零会话／请求计数，整数耗尽抛错，不回绕重用。
2. Open 分配单调递增的 session，并等候回复；成功前不能发 Key／Select。每个连接最多 64 个会话，包括等待建立与等待关闭的会话；超限拒绝创建，不挤掉已有上下文。
3. 每会话最多一个普通待回复请求。Key／Select 请求未完成时再次请求返回空值；这不是按键丢弃策略，未来 TSF 必须自己保留输入事件、限制排队并保持顺序。不同会话可同时有请求，并可乱序完成。
4. Cancel 递增 composition，替代旧待回复请求；支持建立中、输入中及重复取消。只有最新取消回复有效，确认后才能发新 Key／Select。连接的传输顺序必须保持 Open 在 Cancel 之前；服务端取消须清空旧解码状态，不能只改回复编号。
5. Close 递增 composition 并替代待回复请求，立即拒绝该会话的新输入；确认前保留一个关闭状态，确认后移除。建立中的会话也能关闭，迟到的 Open／Key／Select 回复均无效。
6. Reply 必须精确匹配 connection、engine、session、composition、request 五项，且属于当前待回复请求。成功接收一次后清除待回复状态，重复回复不会再次获准交付。匹配的 Error 使整个连接失效；过期或其他会话的 Error 不能关闭当前有效连接。

Open／Cancel／Close 回复仅改变控制状态，不产生文字。未来调用方应保存请求类型和原上下文归属，载荷完整验证通过后再调用 accept；获准的提交只能追加到原上下文的 PendingDelivery，不能按“当前焦点”选择投递对象。

## 超时、断连与焦点

所有时间参数使用调用方提供的同一单调时钟单位；deadline 必须大于 now，到达截止时间即过期。本批不设产品超时常数，也没有自动计时器。未来调用方需要安排唤醒并调用 expire，否则空闲时不会主动发现超时。

任一在途请求或握手超时，清除整个连接的会话与待回复状态，阻止迟到回复。因为选词可能已被服务端执行，禁止自动重放 Key／Select；重连从新会话开始。disconnect 同样只撤销引擎请求，不修改已被客户端确认并存入原上下文的本地投递队列。未收到的选择结果存在不确定性，本批不承诺无损恢复；未来协议需明确确认与恢复机制后才能接入正式输入。

失焦取消的是未确认的组字／引擎响应。已经获准并写入本地队列的文字继续归原上下文，暂停投递，恢复该上下文才继续。上下文销毁由现有 PendingDelivery.close 丢弃其队列。协议取消、传输断开与 TSF 队列生命周期分开处理；不能因重连把旧文字转交给新窗口。

## 验证与下一步

engine_protocol CTest 覆盖固定字节布局、每个截断位置、粘连帧、非法头／版本／类型／保留位／身份、长度上限、2,000 组确定性随机往返及错误版本；客户端覆盖双会话乱序、错身份、重复回复、反复取消、建立中失焦／关闭、握手超时、请求超时、重连、Error 和会话上限。测试用现有 PendingDelivery 检查已确认文字的原队列归属；不模拟真实 TSF 插入，也不等于服务端隔离或安全传输已验证。

接下来按顺序推进：

1. 类型化载荷：按键、简繁与上下文、候选集合版本、稳定候选 ID、消耗范围、选择结果和错误状态；先检查长度／编码／范围，再允许状态变化。明确每次部分提交后组字代次如何同步，拒绝旧候选选择。
2. 服务端调度与会话隔离：按认证连接＋session 管理独立解码状态，取消前的旧任务不能修改新代次；共享只读词库，明确 SQLite 连接的线程归属。测两个客户端相同 session 数字仍隔离、断连释放和超时后不重放。
3. Windows 本地传输：命名管道限制当前登录用户与会话、拒绝远程连接，并验证服务端身份；异步 I/O、有界缓存、半包超时、故障关闭与回调生命周期测试。当前数字身份不提供这些保障。
4. 实验引擎进程接入真实核心，验证简繁／日语／FF14／取消／回退，比较单共享词库与多宿主基线内存和请求延迟。
5. 最后接入 TSF，明确同步按键接受与异步结果的协调、快速输入排队、断连未确认选词恢复。真实应用验收通过后才替换发行默认路径。
