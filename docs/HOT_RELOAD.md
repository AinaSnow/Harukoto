# Windows 热更新计划

状态：alpha.18 实现 WIN-03a 的主题包热更新首版；基础／个人词库和独立引擎尚未实现。2026-11-10 根据 QQ 测试与维护者要求列为 P0 · WIN-03。

## alpha.18 已实现范围

- 已加载 alpha.18 的应用在实际按键时至多每秒启动一次后台检查；读取 CURRENT，只有新代次才验证并合并完整 enabled.tsv。查询按键是否接收的 OnTestKeyDown 不产生副作用。没有持续输入时不轮询磁盘。
- 背景加载完成后，在下一个空组字的实际按键之前切换词库；正在输入时保持旧候选、顺序和消耗索引，翻页、部分选词和 F6 不受切换影响。若修改词库后第一段输入尚未更新，完成或 Esc 取消这一段，再开始输入即可采用已加载版本；不是保证修改后的第一个按键立即生效。
- 空的有效快照表示关闭全部主题；损坏／丢失／不完整快照保留当前词库，并在后续新组字候选标题提示“词库更新失败，沿用旧版”。恢复有效快照后自动重试。后台工作持有模块引用和独立数据，不访问 TSF 对象；服务退出不等待磁盘读取。
- 自动测试覆盖空配置、启停、损坏保留、回退、相同版本去重、加载中退出，以及真实管理器生成的 FF14 113,463 行快照在同一会话的启用／停用／回退和候选选择。QQ／游戏实机操作仍待验收。
- 首次升级到 alpha.18 仍需退出并重开 QQ 等宿主，使新 DLL 加载；之后主题管理不再要求每次重启。普通中文词库、旧个人 TSV、词形表和引擎代码更新仍需重开应用。

## 目标与现状

目标是在 QQ 等输入应用持续打开时更新词库、排序引擎及候选界面，不要求每次都退出应用。当前 MeowpuutTip.dll 直接加载核心和词库，宿主进程保留已加载的 DLL；更新磁盘文件和注册路径不会替换进程里的代码。候选界面已是独立进程，但当前协议与版本路径仍需配套。

本次反馈已确认 QQ／QQKit 的模块路径文件哈希与 alpha.16 注册文件一致，特级恢复药排序在同版探针复现；不能把该候选错误归因为旧 DLL。诊断只比较模块路径文件，不是内存逐字节校验。

## 分阶段交付

1. **WIN-03a：词库快照重载。** 在组字边界检查 CURRENT／版本标识，后台验证完整快照，成功后原子切换。进行中的组字继续引用旧快照，避免候选索引变化；新组字使用新快照。基础、主题、个人词表需要统一的版本信息，损坏文件继续用旧版本并提示。验收：QQ 不重开即可启用／停用主题，输入中更新不丢字，失败与回退可复现。
2. **WIN-03b：稳定 TSF 接入层＋独立引擎进程。** TSF 留在宿主，负责按键接受、焦点、上下文和上屏；引擎负责解码与词库。IPC 明确协议版本、会话、组字代次、请求序号、候选稳定标识和消耗范围；连接限制为当前用户。必须有超时、断连处理和旧响应丢弃，不能卡住宿主线程或把旧上下文文字插入新窗口。兼容性协商失败时保留旧引擎。
3. **WIN-03c：更新协调与回退。** 新引擎通过自检后发布版本指针；空闲会话重连，进行中的组字在完成／取消后切换。候选界面按协议能力更新。保留上一可用版本，覆盖崩溃、更新中断、登录注销、多应用、远程桌面及游戏实测，报告真正生效的接入层／引擎／词库版本。

## 验收边界

- 不在 QQ 等宿主里强行卸载 DLL，不向其他进程注入替换代码。第一次迁移和以后修改 TSF 接入层时仍可能需要重开应用。
- 已确认选词的待投递文字仍属于原 TSF 上下文，与未选中的拼音分开处理；失焦取消未提交组字，不让重新连接重放已上屏文本。
- alpha.18 仅完成主题包热更新；WIN-03a 的其他词库以及 WIN-03b／WIN-03c 继续待实现。
- 先测本机按键到候选与上屏延迟，再决定 IPC 缓存和超时预算；不能仅以核心运算耗时宣称达到商业输入法体验。
