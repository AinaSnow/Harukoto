# Windows 热更新计划

状态：alpha.20 已接入基础中文、SQLite、基础日语与活用表的整包热更新，并与主题／个人表一起合并发布。此机制属于通用 Windows 输入服务，适用于每个加载新版接入层的宿主应用；QQ 只是最早的复现场景。独立引擎代码热更新仍待实现。

## alpha.20 通用基础词库热更新

alpha.21 新增只读运行时诊断：各服务实例在共享内存中报告实际基础标识、待切换标识及最近观察阶段；诊断工具与磁盘发布指针对比。空闲阶段不持续更新，旧版或不可读实例保持未知，不以报告年龄判断应用失联。详见[诊断指南](WINDOWS_DIAGNOSIS.md)。安装基础文件哈希和个人表指纹仍待补。

- 读取当前用户 BaseDictionaries/STATE.json，各输入服务实例在实际按键时至多每秒启动后台检查；所有基础文件验证／解析成功，再与主题和个人表合并。任一来源失败保留当前整套结果，后续重试并提示。发布和回退命令见[快照指南](BASE_DICTIONARY_SNAPSHOTS.md)。
- 正在输入、活用面板开启或任一挂起会话有引擎未取走的已选文字时推迟切换。空组字时先准备所有替代会话，再一并交换，保持各字段的简繁模式／片段上下文。TSF 队列已保存的文字不清空、不转移，加载失败不改旧候选。
- 两个独立测试进程覆盖分别生效、进行中输入／已选文字／挂起会话、失焦、主题个人合并、坏更新恢复和回退；真实全量词库服务测试通过。首次升级仍需重开各输入应用；各实例按需独立切换，不保证发布后首键立即生效。真实按键延迟、内存峰值及各应用投递仍需实测。

## 基础词库版本化准备

- 新增开发用创建／验证／暂存／回退工具，将原生拼音、SQLite、基础日语、活用表作为完整快照管理；内容哈希标识、原子状态指针和独占写锁防止发布半包。见[格式与操作说明](BASE_DICTIONARY_SNAPSHOTS.md)。
- 原生 Snapshot 加载器统一持有四文件加载结果及 SQLite，文件句柄保护已加载快照不被覆盖。alpha.20 TSF 已读取运行时指针；安装器不自动发布用户快照。管理工具仅确认发布，不确认各应用的实际采用版本。

## alpha.19 新增个人词表

- 同一后台工作检查 `%LOCALAPPDATA%/Meowpuut/japanese-custom.tsv`。这是个人拼音／英语到日语的触发词表，不是普通中文用户词频或自动学习。使用现有导入工具发布 UTF-8 六列编译表；导入继续整表替换，不变为追加。
- 比较实际字节，不只看大小和时间戳；相同内容复用解析快照。每次检查读取最多 32 MiB，内容变化才解析和重建合并表，全部在后台执行；大个人表在多应用同时输入时的总体磁盘／内存负载仍待测。
- 使用单个文件句柄读取，允许原子替换，读取期间拒绝原地写入。任意坏行、非法 Unicode／读音、超限或文件占用都会拒绝整个更新。主题和个人表作为一份合并结果在空组字边界发布，任一来源失败时暂缓整份切换并沿用旧表。
- 曾成功加载的个人文件意外丢失时保留内存旧版；显式清空须运行 `python Windows/import-japanese-dictionary.py --clear`，发布有效空表。该命令不影响主题包，也不是自动备份／回退工具。恢复旧词条请重新导入自己保留的源词表。内存旧版只在当前进程存活期间保留。
- 原有基础日语／个人／主题的同权重稳定顺序保持，主题更新不会把旧个人词条重新带回。自动测试含同大小同时间替换、CRLF、锁定文件、损坏和恢复、显式空表、主题与个人表共存，以及真实 Python 导入结果经 C++ 合并后的简繁候选。QQ／游戏实机验收待执行。

## alpha.18 已实现范围

- 已加载 alpha.18 的应用在实际按键时至多每秒启动一次后台检查；读取 CURRENT，只有新代次才验证并合并完整 enabled.tsv。查询按键是否接收的 OnTestKeyDown 不产生副作用。没有持续输入时不轮询磁盘。
- 背景加载完成后，在下一个空组字的实际按键之前切换词库；正在输入时保持旧候选、顺序和消耗索引，翻页、部分选词和 F6 不受切换影响。若修改词库后第一段输入尚未更新，完成或 Esc 取消这一段，再开始输入即可采用已加载版本；不是保证修改后的第一个按键立即生效。
- 空的有效快照表示关闭全部主题；损坏／丢失／不完整快照保留当前词库，并在后续新组字候选标题提示“词库更新失败，沿用旧版”。恢复有效快照后自动重试。后台工作持有模块引用和独立数据，不访问 TSF 对象；服务退出不等待磁盘读取。
- 自动测试覆盖空配置、启停、损坏保留、回退、相同版本去重、加载中退出，以及真实管理器生成的 FF14 113,463 行快照在同一会话的启用／停用／回退和候选选择。QQ／游戏实机操作仍待验收。
- 首次升级到支持对应功能的版本仍需退出并重开宿主应用，使新 DLL 加载；之后主题（alpha.18 起）、个人表（alpha.19 起）、基础中文与活用表整包（alpha.20 起）可热更新。引擎代码更新仍需重开应用。

## 目标与现状

目标是在各 Windows 输入应用持续打开时更新词库、排序引擎及候选界面，不要求每次都退出应用。当前 MeowpuutTip.dll 直接加载核心，宿主进程保留已加载的 DLL；更新磁盘文件和注册路径不会替换进程里的代码。候选界面已是独立进程，但当前协议与版本路径仍需配套。

本次反馈已确认 QQ／QQKit 的模块路径文件哈希与 alpha.16 注册文件一致，特级恢复药排序在同版探针复现；不能把该候选错误归因为旧 DLL。诊断只比较模块路径文件，不是内存逐字节校验。

## 分阶段交付

1. **WIN-03a：词库快照重载（首版已实现）。** 基础／主题／个人表在后台验证并统一发布，正在输入沿用旧表。继续补各应用实际生效版本诊断与性能测试；记事本、浏览器、VS Code、QQ、FF14 和远程环境验收输入稳定、上屏、失败恢复与回退，不按应用名称编写专用逻辑。
2. **WIN-03b：稳定 TSF 接入层＋独立引擎进程。** TSF 留在宿主，负责按键接受、焦点、上下文和上屏；引擎负责解码与词库。IPC 明确协议版本、会话、组字代次、请求序号、候选稳定标识和消耗范围；连接限制为当前用户。必须有超时、断连处理和旧响应丢弃，不能卡住宿主线程或把旧上下文文字插入新窗口。兼容性协商失败时保留旧引擎。
3. **WIN-03c：更新协调与回退。** 新引擎通过自检后发布版本指针；空闲会话重连，进行中的组字在完成／取消后切换。候选界面按协议能力更新。保留上一可用版本，覆盖崩溃、更新中断、登录注销、多应用、远程桌面及游戏实测，报告真正生效的接入层／引擎／词库版本。

## 验收边界

- 不在 QQ 等宿主里强行卸载 DLL，不向其他进程注入替换代码。第一次迁移和以后修改 TSF 接入层时仍可能需要重开应用。
- 已确认选词的待投递文字仍属于原 TSF 上下文，与未选中的拼音分开处理；失焦取消未提交组字，不让重新连接重放已上屏文本。
- alpha.20 完成 WIN-03a 基础／主题／个人表首版重载；跨应用实测与生效版本诊断未完成，WIN-03b／WIN-03c 继续待实现。
- 先测本机按键到候选与上屏延迟，再决定 IPC 缓存和超时预算；不能仅以核心运算耗时宣称达到商业输入法体验。
