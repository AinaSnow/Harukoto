# 引擎与词库

## 执行时

Core/MeowpuutCore.cpp 提供 C++17 中文解码器与 C API。不可变词表供会话共用，每个会话独立保存组字、候选、页码与提交内容。拼音和注音各有读音索引，共用词条字形与频率来源。

模糊音（CN-03）按会话开关：`mpn_set_fuzzy_pinyin` 接受 `MPN_FUZZY_*` 位掩码（11 对，默认 0 即关闭，关闭时结果与没有此功能时逐项相同）。解码前，解码器把输入切成完整拼音音节（声母＋韵母，且替换后的拼写必须是词库里有单字的读音），对每个音节按已开启的对替换声母、韵母或两者，再从每个起点沿“词库里有以此开头的读音”向后走，得到每段输入可以代表的词库读音及替换次数（每个词最多 3 处，每个起点最多走 1024 步、记 64 个读音）。只有声母的简拼音节不替换；声调和隔音符只能落在音节之间，输入的声调须与词的声调一致。组句时这些读音的完整拼写词与精确词一起参与，并另占一份与精确词等宽的搜索宽度，不会被满宽的精确词挤掉。开了某对的人听不出这对的区别，所以模糊词主要按频率与精确词竞争：同一段按键上有完整拼写的精确词时，每处替换扣 5 奈特（频率约差 150 倍以上才胜出，相近时精确读音优先）；没有精确词时，精确的组合可能只是词库缺词（点赞 只能拆成 点＋赞），所以只有常用的模糊词（词库权重至少 4500，约前 1.5% 的词条）扣 5 奈特，其余扣 8 奈特（电站 排在 点赞 之后）。覆盖整段输入的模糊词：有精确整词时，权重减每处 3500 后高于最弱的精确整词的，按权重并入整词列表（sijian：时间 在 四溅、四件 之前），否则按 8 奈特留在整句候选中；没有精确整词时，只有得分压过所有精确整句的才放进整词列表。并入的词若已作为 n／ng 纠错出现，改按模糊音的位置排列。用到替换的候选来源标为 `MPN_CANDIDATE_CORRECTION`，`mpn_candidate_fuzzy` 返回 1，`mpn_candidate_words` 对它返回空。Windows 候选合并把查询数据库里有该读音证据的词排前，但核心已排在这类词之前的模糊词保持原位。逐段兜底（句首词、首音节单字、分段整句、未完成音节的前缀等）只用精确读音。

简拼与混拼（CN-04）始终开启，不需要设置。只有当输入不能切成完整音节（词库里有单字的读音，不跨声调和隔音符）、且整串不是某个完整拼写词的读音时才启用，所以完整拼音的候选与没有此功能时逐项相同。启用时，输入的一段可以是声母，代表一个完整音节：一个字母（z、c、s 也代表 zh、ch、sh；a、o、e 代表以它开头的音节）或 zh、ch、sh。载入时为两到八个音节的完整拼写词建“首字母键”索引（每个音节取首字母，每个字母 5 位压成 64 位整数，同前缀的键连续；约 38 万项、4.4 MiB），解码时从每个起点把输入切成完整音节与声母的组合，只在索引里有以此开头的键时继续（每起点最多走 256 步、记 32 种切法），找到的词须音节数相同，完整音节逐字相同、声母是音节的开头，输入的声调须相符。这些词与精确词一起组句，另占一份与精确词等宽的搜索宽度（每种切法最多看索引 1,024 项、取两倍宽度的匹配），分数为词频减每个简拼音节 2 奈特（`abbrev_penalty`），所以同一串按键里拼全的音节越多越优先（zgren 是 中国＋人，不是 中国人＋嗯）；同一段按键上有完整拼写的精确词时这段不出简拼词。较长输入中间只有两个声母的一段（如 zg）只取权重至少 4000 的词；整串以外单独成段的一个声母可以代表一个常用单字（权重至少 5000，扣 4 奈特，wobzd 的“不”）。启用时词库里编译器生成的纯声母缩写行（权重为全拼的 1/8）不再参与，由索引代替。用到简拼的候选来源标为 `MPN_CANDIDATE_CORRECTION`，`mpn_candidate_abbreviated` 返回简拼音节数，`mpn_candidate_words` 返回空（不按词学习）；个人词频按词的完整读音查。解码器把简拼候选排在第一时，它排在逐段前缀候选之前；只有末尾一个声母是简拼时（nihaom），这个声母可能是下一个音节的开头，完整拼音的前缀（你好）保持第一，简拼补全（你好吗）排第二。模糊音不替换声母。

纠错（CN-05）按会话开关：`mpn_set_typo_correction`，默认开启。输入不能切成完整音节、没有声调和隔音符、不超过 40 个字母时，解码器假定其中可能有一处手误：相邻两个字母颠倒（zhogn、nihoa、womne）、漏一个字母（zhonguo）、多一个字母（nihhao、zhonggguo）或按到键盘相邻键（只限元音换元音、辅音换辅音）。从每个起点沿输入的精确前缀走，在每个位置各试一次这四种改动，改动后继续逐字匹配，只在“词库里有以此开头的读音”时继续，记下与一段输入只差一处改动、且含完整拼写词的读音（每起点最多 4,096 次前缀查找、256 个读音）。为免把未打完的音节当成手误：除了末尾两个字母颠倒，改动后至少保留最后两个按键原样（zhongg 仍是简拼“中国”，jiag 不补成 jiang）；改动的那段输入必须含元音（zhd 仍是简拼）；输入能读成完整音节加一个音节的开头（budin、jiaobe）时整串不纠错。这些词与精确词、模糊词、简拼词一起组句，另占一份与精确词等宽的搜索宽度，分数为词频减 3 奈特（`typo_penalty`）；只纠正成常用词（权重至少 4500），整串以外只纠正成两字以上的词（纠正出的单字会把 wosuki 这类罗马字拼成“我素力”）。每个候选最多一个纠错词，且不与简拼词同在一个候选里；同一段按键上有完整拼写的精确词或模糊词（开启模糊音时）就不出纠错词，所以精确和用户开启的模糊读音先于纠错。纠错与简拼都在“切不成完整音节”时启用，二者按分数竞争：一个常用词的纠错（zhogn→中，单个词扣 3 奈特）胜过把同一串拆成多个简拼词的拼凑（中＋喔＋功能，各简拼音节扣 2 奈特且多一个词）；只打声母的串（zhd、bkn）和未打完的末尾声母（zhongg、nihaom）因上面的限制不出纠错，仍按简拼。解码器第一项是纠错时，它与简拼一样排在整串键盘纠错兜底和逐段前缀候选之前。能切成完整音节的输入照旧精确解码；只在整串没有完整拼写的词时，把与整串只差一处颠倒、漏字母或多字母、权重至少 4500 的两字以上的词（最多 2 个）放在第 4 位起（zhonggou→中国、doushao→多少），前三项不变。原有的整串局部纠错（键盘相邻、颠倒、重复字母、n／ng）和整词列表里的 n／ng 纠错保留，同属这个开关：关闭后不出任何基于手误猜测的候选，前缀补全照旧；关闭时结果因此与改动前不同（少了原有的纠错）。纠错候选来源标为 `MPN_CANDIDATE_CORRECTION`，`mpn_candidate_typo` 返回 1（原有的整串纠错也返回 1），`mpn_candidate_words` 返回空。

Windows/MixedComposition.h 合并中文与日语候选，支持显式拼音／英语触发及读音标注。不是完整日语句法解码。

## mimo 1.0 统一词库

编译器 scripts/compile-native-lexicon.py 的合并顺序：
1. 校验两份上游快照的 SHA-256。
2. 读取 McBopomofo 的字形、读音和词频，配对简体字形。
3. 将 Pinyin Pro 带调拼音正规化，按简体词面、带调读音与繁体词面合并；相同简体与读音的不同繁体字词各自保留，不同读音不合并。
4. 保留原有 `weight`，包括用共同词条的对数频率差中位数校准繁体独有词尺度、再减 350 的既有规则。另按「简体字形＋完整带调读音」查 Pinyin Pro 分数，作为 `hans_weight`；没有直接匹配时回退 `weight`。两个分数是排序先验，并非两份语料真实使用量的统计比较。
5. 套用本地修订。明确修订的词条在两种字形均沿用人工权重，即使低于上游；衍生单字仍照来源配对及读音核对。`Resources/Lexicon/simplified-priorities.tsv` 另记只影响简体排序的编辑权重：每项须有同简体词面及带调读音的 Pinyin Pro 来源，且不得与双字形人工词条冲突；这些权重是产品排序决定，不是实测词频。生成的 manifest 记录文件校验值。繁体独有的多字词（简体词面与读音都没有 Pinyin Pro 来源）在简体中原本沿用繁体刻度；若同一无声调读音下分数最高的有来源词在句子语料中至少出现 20 次，而这个繁体独有词不足 20 次，且语料切分会把它当作整词计数（否则它的计数没有意义，如“我是”会被切成“我＋是”），它的 `hans_weight` 降到该词之下 1 分，最多降 1400 分（2 奈特）；`weight` 不变，人工词条和 `Resources/Lexicon/simplified-traditional-only-keep.tsv` 中人工复核豁免的词不受影响。被调整的条目写在 `simplified-traditional-only-audit.json`，manifest 记录条数与 word-priors 的校验值。按逐字对齐和 `ni3` 读音处理「妳」的简体显示，生成的 `simplified-pronoun-audit.json` 记录处理项目。
6. 输出完整 SQLite 词库与拼音、注音读音索引。V2 索引表头为 `MEOWPUUT-PINYIN-2` 或 `MEOWPUUT-ZHUYIN-2`，数据行依序为 `bare`、带调读音、繁体、简体、`weight`、`hans_weight`；行的排序和原五栏与旧版一致。SQLite 的 `lexicon` 也保留 `weight` 并另设 `hans_weight`，供简体查询排序。

V2 的 `# context` 区以繁体词面为键，每行依序存放繁体和简体上下文权重，分别从同一词面的完整读音取对应模式最高分；`context.tsv` 的人工优先级同时适用两种模式。新版解码器也接受旧版只有一个上下文权重的数据，将该权重用于两种模式；旧版解码器不能读取新的三栏上下文，程序与数据须一起更新。这些上下文分数是排序依据，并不保证完整句子的语意正确。

拼音索引在上下文区之后还可以有一段可选的统计数据，以单独一行 `# statistics` 开头，只影响组句。其中依次是四个区，各自按字节序升序排列：`# authored` 逐行列出来自 `context.tsv` 的人工短语（必须已在上下文区出现）；`# priors` 为 `简体词<TAB>修正值`，把词在句子里的得分向它在连续文本中的频率移动，单位是百分之一奈特，范围正负 999 且不为零；`# pairwords` 逐行列出参与搭配的简体词，行号（从 1 起）就是它的编号，`^` 和 `$` 表示短语的开头和结尾；`# pairs` 为 `左词编号<TAB>右词编号<TAB>分数`，是相邻词搭配分数（1 到 999）。格式不对时整份词库拒绝加载。解码器直接从调用方的缓冲区解析这段数据，不保留原文。数据来自句子语料统计，见 [句子语料说明](../DataSources/SentenceCorpora/README.md)。`simplified-priorities.tsv` 里有简体编辑权重的词不写负的修正值（语料只能在句中抬高它，不能把编辑决定拉回去）。有搭配数据时，解码器把“相邻两段拼起来恰好是词库里的词”这一项旧的加分减半，人工短语的加分提高到 1.5 倍；没有这段数据时行为与之前相同。单独输入一个词时的同音词顺序不受影响。旧版解码器不认识这段数据，会拒绝加载，程序与数据须一起更新。注音索引不写这段数据。

字形转换使用随项目提供的固定 ICU 78.2 转换快照与人工覆盖；保留的平台离线构建使用同一份数据。缺少新词的转换时会停止构建，经审核后更新快照。没有明确对应的新词可能遇到一简对多繁的歧义，应以本地修订校正。合并不会删掉繁体专有表达或多音字；同义但不同写法也不冒充重复词。

lexicon-merge-report.json 记录去重、来源新增、排除数量、频率校准与索引规模。V2 词库须与支持 V2 的程序一起发布；旧版程序不能读 V2。单字查找、前缀补全和误拼修正使用有界搜寻；不会在每次按键时扫描整份词库。

`scripts/audit-mimo-corpus.py` 的第二版审核报告分别列出 `traditional_weight` 和 `hans_weight`，简体变体按后者排列；审核旧 SQLite 时以 `weight` 作简体回退并明确标示。分数本身不能证明词条由哪个来源提供，来源证据仍须另行核对。

## 更新与个人词库

python3 scripts/update-simplified-lexicon.py 只检查上游；加 --apply 才更新快照。更新后重新构建、执行 Windows 回归与数据检查，不在用户输入时下载数据。

Windows 暂未实现完整个人选词学习；本地自定义日语词表与系统词库分开保存。旧 Swift 适配层已移除。

## 测试边界

Windows 构建脚本运行 CTest，Python 测试覆盖词表及日语活用原型。实际 TSF 生命周期和应用兼容性参阅 WINDOWS_VALIDATION.md。
