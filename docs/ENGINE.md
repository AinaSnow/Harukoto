# 引擎与词库

## 执行时

Core/MeowpuutCore.cpp 提供 C++17 中文解码器与 C API。不可变词表供会话共用，每个会话独立保存组字、候选、页码与提交内容。拼音和注音各有读音索引，共用词条字形与频率来源。

Swift 的 ChineseWithJapaneseBackend 合并候选。英文判断使用本机规则；日语使用 Romaji 转假名与小型单字表。收合时保留一个日语候选，展开后按引擎排序显示；完整中文候选和已学会的用词仍会参与排序。这不是通用语言辨识或完整日语句法解码。

## mimo 1.0 统一词库

编译器 scripts/compile-native-lexicon.py 的合并顺序：
1. 校验两份上游快照的 SHA-256。
2. 读取 McBopomofo 的字形、读音和词频，配对简体字形。
3. 将 Pinyin Pro 带调拼音正规化，按简体词面、带调读音与繁体词面合并；相同简体与读音的不同繁体字词各自保留，不同读音不合并。
4. 保留原有 `weight`，包括用共同词条的对数频率差中位数校准繁体独有词尺度、再减 350 的既有规则。另按「简体字形＋完整带调读音」查 Pinyin Pro 分数，作为 `hans_weight`；没有直接匹配时回退 `weight`。两个分数是排序先验，并非两份语料真实使用量的统计比较。
5. 套用本地修订。明确修订的词条在两种字形均沿用人工权重，即使低于上游；衍生单字仍照来源配对及读音核对。`Resources/Lexicon/simplified-priorities.tsv` 另记只影响简体排序的编辑权重：每项须有同简体词面及带调读音的 Pinyin Pro 来源，且不得与双字形人工词条冲突；这些权重是产品排序决定，不是实测词频。生成的 manifest 记录文件校验值。按逐字对齐和 `ni3` 读音处理「妳」的简体显示，生成的 `simplified-pronoun-audit.json` 记录处理项目。
6. 输出完整 SQLite 词库与拼音、注音读音索引。V2 索引表头为 `MEOWPUUT-PINYIN-2` 或 `MEOWPUUT-ZHUYIN-2`，数据行依序为 `bare`、带调读音、繁体、简体、`weight`、`hans_weight`；行的排序和原五栏与旧版一致。SQLite 的 `lexicon` 也保留 `weight` 并另设 `hans_weight`，供简体查询排序。

V2 的 `# context` 区以繁体词面为键，每行依序存放繁体和简体上下文权重，分别从同一词面的完整读音取对应模式最高分；`context.tsv` 的人工优先级同时适用两种模式。新版解码器也接受旧版只有一个上下文权重的数据，将该权重用于两种模式；旧版解码器不能读取新的三栏上下文，程序与数据须一起更新。这些上下文分数是排序依据，并不保证完整句子的语意正确。

字形转换使用随项目提供的固定 ICU 78.2 转换快照与人工覆盖；四个平台离线构建使用同一份数据。缺少新词的转换时会停止构建，经审核后更新快照。没有明确对应的新词可能遇到一简对多繁的歧义，应以本地修订校正。合并不会删掉繁体专有表达或多音字；同义但不同写法也不冒充重复词。

lexicon-merge-report.json 记录去重、来源新增、排除数量、频率校准与索引规模。V2 词库须与支持 V2 的程序一起发布；旧版程序不能读 V2。单字查找、前缀补全和误拼修正使用有界搜寻；不会在每次按键时扫描整份词库。

`scripts/audit-mimo-corpus.py` 的第二版审核报告分别列出 `traditional_weight` 和 `hans_weight`，简体变体按后者排列；审核旧 SQLite 时以 `weight` 作简体回退并明确标示。分数本身不能证明词条由哪个来源提供，来源证据仍须另行核对。

## 更新与个人词库

python3 scripts/update-simplified-lexicon.py 只检查上游；加 --apply 才更新快照。更新后重新构建、执行 --smoke 与数据检查，不在用户输入时下载数据。

ChoiceMemory 只学习已确认选词，以及短时间相邻选词形成的短语。数据保存在本机，与捆绑词库分开，可停用或清除。没有聊天记录读取或云端同步。

完整选过至少两次的中文长句也能成为个人候选，不再只回用八字以内的词。记录仍限制为每条最多 100 字、读音最多 256 字符、每个读音八个选项及总共 5,000 个读音。若同句已由核心解码，沿用它原本的候选索引和读音消耗信息；同文但只转换前段的候选仍分开保留。这条个人记忆路径目前由 macOS／iOS 的共享 Swift 适配层使用。

## 测试边界

--smoke 涵盖繁简、拼音／注音模式隔离、误拼、单字母、长句、候选翻页、日语保留、个人记忆与候选尺寸。它不是输入准确率评测；毫秒测量也只是测试批次内的引擎耗时，不等于端到端输入延迟。

Windows 的 TSF 输入服务仍需在真机和不同应用中验证。iOS 尚需真机内存、跨 App、安全输入字段与无障碍验证。
